## Overview
Implements spec-evidence-identity-an-attested-row-counts-only-for-the (AC-EI-1..3). The rule lands and the ACs it drops are re-verified in ONE phase, so main never carries an unexplained red band (user decision 2026-10-18).

| T | Task | AC |
|---|---|---|
| EI-1 | Coverage counts only equal-command attested rows (pass and fail); other_command tally on every surface | AC-EI-1 |
| EI-2 | Missing-oracle detection covers script paths; any missing oracle renders not_measured (TG-22 narrowing removed); ac add/set refuse a missing script path | AC-EI-2 |
| EI-3 | Drop-set snapshot (before/after `lore ac list --json` dumps) + scripts/check-evidence-identity-drop-set.ts | AC-EI-3 |
| EI-4 | Re-verify the drop set on main; triage every remaining red (fix, correct, or a task) | AC-EI-3 |

Dependencies: EI-3 blocks EI-1; EI-1 blocks EI-2 (both edit packages/core/src/acceptance.ts deriveAcCoverageState); EI-1 and EI-2 block EI-4. One phase: "Phase 1: rule and re-verification".

Merge sequence (the rule reaches main as ONE step, then EI-4 at once):
1. EI-3 merges to main first: checker + generator + fixture tests only. The checker is NOT wired into `bun run test` or any gate in this window (its exit-2 path would turn main red); its own tests use fixtures.
2. EI-1 is implemented and reviewed in its worktree but NOT merged to main on return. EI-2 is dispatched in a worktree branched from EI-1's branch head, so it carries EI-1.
3. When EI-2 returns: the orchestrator takes the BEFORE dump (`lore ac list --json`, every live spec) on main, then merges EI-1 and EI-2 back to back with no other merge between, rebuilds, and takes the AFTER dump. The drop set therefore covers drops from both AC-EI-1 and AC-EI-2.
4. EI-4 starts immediately: commits the drop set, wires check-evidence-identity-drop-set.ts into the test chain, re-verifies, triages.

Baseline measurement (2026-10-18, main dea310e9 era, read-only): 1008 attested_pass script ACs, 292 drop under strict equality (263 last changed in the TG-23 runner rewrite; 29 older, of which 24 are genuine mismatches and 5 differ only by a trailing echo/2>&1), 13 fail ACs turn green under the symmetric rule, 1 script-path oracle missing (AC-TG-11; lands with TG-15), 0 ACs affected by removing TG-22's narrowing today. Data: scratchpad evid-identity/flippers.json (to be regenerated by EI-3 at merge time, not reused).

## Invariants
- INV-1: no normalisation of commands; a drop is fixed by re-verifying or by a recorded `lore ac set --correction`, never by widening the equality.
- INV-2: main stays green: check:ac-oracle-ownership holds via not-built ledger rows for AC-EI-1..3 until each oracle lands; the rule reaches main only as the EI-1+EI-2 pair (merge sequence step 3), immediately followed by EI-4; the drop-set checker joins the test chain only in EI-4 together with its data; the full suite runs once after EI-4.
- INV-3: every oracle is red-first in its own task with exact exit codes and the rule name asserted.
- INV-4: lore done's archival floor (BR-200) is NOT changed here; it stays an open question to the user.
