# Fragment injection timing

## Goal

Land spec-fragment-injection-timing-one-inject-enum-a-per-turn: one `inject` timing enum replaces `audience`/`mode`/`delivery`, a per-turn `hook:user-prompt` outlet delivered by a UserPromptSubmit hook, `context.artifact_language` as `{{lore:artifact_language}}`, and `lore migrate fragments`.

## Preconditions

Spec approved.

## Tasks

- I1 (phase I, first): schema + routing re-key, outlet id and render side of `hook:user-prompt`, check/refresh/list/run re-key, shipped AND this repo's project fragments rewritten by hand, every test fixture moved, assets manifest regenerated. AC-IT-1, 2, 3, 7, 8, 9, 10, 11.
- I2 (phase W, after I1): `assets/hooks/user-prompt-fragments.mjs` (fast path, 3 s spawn, banner) + registration + hook-count pins + manifest. AC-IT-4.
- I3 (phase W, after I1): `context.artifact_language`, shared `languageName`, `configVariableValues` → Result. AC-IT-6.
- I4 (phase W, after I1): `lore migrate fragments`. AC-IT-5.

I1 is one task because removing the old fields breaks compilation of every consumer at once. In phase W, I2/I3/I4 run in parallel; I2 and I3 both touch no common source file, the shared generated manifest is regenerated by whichever lands second (merge main into the branch on conflict).
