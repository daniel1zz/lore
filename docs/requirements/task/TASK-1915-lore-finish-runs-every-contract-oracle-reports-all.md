Approach: `task-finish-service.ts` (new) implements the code-task flow: resolve the claim of the caller run, refuse a claim whose branch is the plan's integration branch or is recorded by another live claim (`shared-branch`), check the worktree (clean, cwd inside it), read HEAD once as `preRunHead` before anything runs, run every oracle at that commit (the AC oracles by AC id through the verify runner, each test oracle as an unfiltered whole-file run through the `test_file` template, typecheck) even after one fails, derive the write-set additions and persist any missing one, and record ALL rows (stamped with `preRunHead`), the additions and `finished_at`/`finished_commit` in ONE corpus write with `expectedVersion`, a claim-holder check, and a re-read of HEAD and the tree (a changed task, a taken-over lease, a moved HEAD or a dirty tree is exit 5 and records nothing). The row recording is a new `recordVerifiedEvidenceBatch` on `TaskWorkflowService` reusing the existing runner-attestation path, so there is one copy of the attestation rules. With `--red` it runs only the AC oracles and applies the BR-1077 summary check. An AC superseded after approve is refused `ac-superseded`. `commands/finish.ts` registers the verb in `adapters/cli/index.ts`; `app.ts` constructs the service. A claim is finished only while `isFinishedInForce(claim, tipOf(claim))` holds (the branch tip equals `finished_commit`; a gone branch is moot and the landed tip of BR-1423 decides): `endRunClaims` skips it, `claim()` refuses another run's claim on it (CLAIM_CONFLICT, exit 5) and `isClaimStale` is false for it (BR-1040), `--steal` still takes it, and a later commit makes it an ordinary claim again; `done()` of a task whose claim records a `finished_commit` refuses `finish-stale` (a `DoneFloorId` added by D, exit 4, second in the floor order, naming the commits made after finish and `lore finish`) when the tip of THAT TASK'S OWN branch is not that commit: the branch ref while it exists, else the tip recorded for the task's claim at release or landing (`end_tip`, or the landing record's `branch_head`); with no recorded tip `done()` refuses `finish-tip-unknown` (exit 4), never a guess, and never compares against the integration or landing commit (a left-over task of an integration-branch plan is judged by its own branch). The overlap computations (`gate-predicates.ts`, `checkpoint-registry.ts`, the ready report) skip a finished claim only when its `finished_commit` is an ancestor of the claiming task's base tip (the contract base branch, else main). `done()` releases a finished claim on success.
