# Pilot v3: execution branch build log (W1a excavation, W1b apply, W1c citations)

Plan `plan-baseline-pilot-v3-populate-the-execution-branch-with`. Two read-only agents drafted 4 leaves each (X: plan, task, claim, evidence; Y: verify, red, archive, close) from main ad8c8e3f, checked every rule against code (file:line) and proposed a citation only where they opened the test the AC's command runs and found a specific test that fails if the rule is false. The orchestrator machine-checked all 93 cited ACs (live spec, script mode, <= 10 cites) — 0 failures — and applied everything from main. Probe v3 was frozen (03:07:39Z) before the branch document was created.

## Outcome
- 8 leaves, 132 rules (BR-97..BR-228), 41 glossary terms, 40 cross-leaf depends-on edges.
- 93 rules cited by >= 1 falsifying script-mode AC (143 citations on 93 ACs); 39 unconfirmed (27 drafted unconfirmed by the excavators — 23 by X, 4 by Y — plus 12 established/observed downgraded by the orchestrator at write time because they had no citation); each has an open question in its leaf.
- 6 citations (EXCL-1/2/3/18, EXEV-1/14 -> AC-WH-2) are INCIDENTAL: the AC runs a whole test file whose failure the rule would cause, but the AC's topic is worktrees. Kept because the placement ADR's Q3 criterion is falsification, not topic; flagged here so a reader can discount them.
- 14 ACs that run the whole suite were excluded as citations (no discriminating power).
- After W1c: both branches together have 0 of 148 established/observed rules without a citing script-mode AC; 135 of 228 rules have passing attested evidence; 0 contradicted.
- Evidence note: on W1b the first expected-fail row (v3) failed because of a grep escaping error in the orchestrator's command, not because of the mutation; a correct red row (v4) was recorded after it. Same pattern earlier on W0a (row v3). Both bad rows remain on the tasks.
