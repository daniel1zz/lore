# Attributable writes — Opportunity Solution Tree

`/lore-product opportunity`, 2026-10-11. Fills the gap recorded in `knowledge-agent-identity-validation-ledger` ("No opportunity tree"): that ledger ran AFTER a discussion produced S1–S4; this tree derives the solution space from the outcome. Solution sets for O1–O4 were generated by four independent read-only subagents (one per opportunity, given the outcome, the opportunity's evidence and the axes table) to reduce anchoring on the discussion's preferred design. Numbers re-verified by the orchestrator are marked ✓.

## Outcome (exactly one)

**Share of claim + evidence + handoff writes that name exactly ONE attested executing run: 0% → ≥95%, measured over 2 weeks after rollout.**

Baseline (2026-10-11): evidence 0 of 806 rows in the last 30 days carry any run, session or agent discriminator ✓ (evidence keys: oracle, command, result, output_tail, recorded_at, recorded_by, ac_ref, attestation, capture_source, ac_oracle_generation); claims carry `session_id` on 847 of 847 rows ✓, but a session and all its subagents share one `session_id` (validation ledger F3), so a claim names a session, not a run. "Attested" = the identity was supplied by a mechanism the writer cannot set (harness/hook, credential), not by `--by` / `$LORE_ACTOR`.

## Opportunities

| # | Opportunity (the executor's / maintainer's words) | Evidence | Tier |
|---|---|---|---|
| O1 | "When I pick up a task I can't tell whether another run is still working on it — and when I take it over, nobody can tell a takeover happened." | 2026-08-11: 2 same-task same-actor takeovers of a fresh lease with no release, treated as a refresh (ledger V1); 2026-08-02: two orchestrators collapsed into one actor, a live agent's worktree removed twice (`task-two-concurrent-orchestrators-both-resolve-to-agent-main`); SPEC-025 §1 gap 3 (KN-001 re-dispatch) | E1 ×3 |
| O2 | "When I read who did something, I can't tell which run it actually was — so I can't hold the right run to account or ask it about its work." | 775 distinct `recorded_by` values over 5,657 evidence rows; 1,789 (32%) under one literal shared by concurrent sessions; the same write shows `system` on `lore get`/`lore log` and the real actor in `audit` (`task-lore-create-by-is-accepted-and-ignored-cli-content-writes`, "made me accuse the wrong agent"); `audit.session_id` holds `gate-passed` on 1,851 rows and document ids elsewhere, never a session; 2026-10-11 a stale shell-profile `LORE_ACTOR` attributed every session's and subagent's writes to one name | E1 ×4 |
| O3 | "After a batch of runs I can't tell whether everything each run produced — branches, commits, worktrees — was collected back; work silently gets left behind." | Recorded in standing rules, not re-measured here: an orphan branch holding 726 lines / 38 regression tests from a nested sub-agent; 14 tasks whose merges carried no slug, so `lore assess` found no commits; issue #106 (merged worktrees never cleaned, cleanup depends on memory); the 2026-08-02 worktree removal | E1 (recorded, secondhand) ×3 |
| O4 | "I can't learn which agent setup (norms, capabilities, memory) produces better work, so changes to agent setup are guesses." | Measured: ~117 commits to agent-setup assets since 2026-07-01 (36 skills/agents + 81 context/project/governance/hooks ✓) and 0 documents comparing any change's effect; review judgments are the only versioned component (1,315 rows with `judge_prompt_version` ✓). Harm from guessing: only the maintainer's stated wish | E1 (gap exists) + E6 (harm) → ⚠️ unevidenced harm |

**Rejected as an opportunity**: "identity must not depend on OS environment variables." It is a cause of O1/O2 and names a mechanism; it fails detector rule 3 (one obvious fix). Its evidence (the shell-profile leak, the dispatch-bundle `export LORE_ACTOR` discipline) is carried under O2.

Independence: satisfying O1 does not require O2 (fencing tokens or a stricter refresh rule fix takeovers without any run identity), and O2 does not require O1. O3 and O4 both benefit from O2's run identity but have solutions that need none.

## Solutions

Kill conditions were set by the generating subagent before any of these experiments were run. Axes: Remove / Automate / Assist / Defaults / Borrow (pattern recalled from memory, unverified) / Absurd. "No identity" = needs no new identity registry.

### O1 — takeover visibility

| # | Solution | Axis | Smallest disproving experiment | Kill condition | Cost |
|---|---|---|---|---|---|
| O1-S1 | A fresh claim is no longer idempotent: renewal happens only through evidence (already exists); any second `claim` on a fresh lease is a takeover requiring `--steal`, audited. No identity. | Remove | Read-only replay of 30 days of claim history: same-actor re-claims of a fresh lease, same vs different `session_id`, evidence in between | Legitimate same-session re-claims ≥20% of such events, or ≥1 false conflict per 10 tasks in a 3-day shadow run | hours–1 day |
| O1-S2 | "Same holder" becomes `(by, session_id)`; missing `session_id` counts as different. Existing fields only. | Defaults | Same replay: share of same-actor re-claims with different `session_id` | <50% cross-session (then the collisions are between subagents of one session, which this cannot see) | hours |
| O1-S3 | Hook-injected run id (SubagentStart records `agent_id`; PreToolUse strips any model-supplied run argument and injects run + HMAC with a hook-held key); lore accepts only verified runs | Automate | 20 parallel headless subagents, 5 told to forge a run id | <95% writes with a valid run, ≥1 forgery accepted, or MCP writes >10% while MCP args cannot be rewritten | 3–5 days |
| O1-S4 | Show liveness at claim time ("held by session X, heartbeat N min ago, process alive/exited", reusing `SessionService.deriveSessionLiveness`); on takeover write a `takeover` event and warn the old holder on its next lore command. No identity. | Assist | 1-week shadow run | >30% still take over a holder shown alive, or >30% of notified holders keep writing | 1–2 days |
| O1-S5 | Fencing token: each claim returns a monotonically increasing epoch; evidence/handoff/release must carry the current epoch, stale epochs refused — a takeover surfaces when the displaced run next writes. A capability, not an identity. (Borrow: Kleppmann's fencing tokens, Chubby sequencers, Kubernetes Lease `leaseTransitions`) | Borrow | Reproduce the 2026-08-11 double-session case in a test; 2-day pilot | >5% of writes refused for a lost epoch | ~1 week |
| O1-S6 | lore becomes the executor: `lore run <task>` launches every run itself via `claude -p`, issues the run id, forbids in-session subagents | Absurd | 1-day prototype, 1-week use | >50% of work still via in-session subagents in a week, or per-task tokens >2× | weeks |

Exposed constraint (S6): only whoever launches the process can truly prove which run executes; Claude Code subagents are spawned inside the main process, beyond lore's reach — so attestation must live at the hook layer.

### O2 — attribution

| # | Solution | Axis | Smallest disproving experiment | Kill condition | Cost |
|---|---|---|---|---|---|
| O2-S1 | Remove free-text attribution: content writes stop accepting `--by` / `$LORE_ACTOR` / MCP `by`; every surface shows the single audit-resolved actor; a write with no known run is labelled `unattested:session-<8>`, never guessed. No identity. | Remove | Read-only replay of 30 days: compare `recorded_by` to `audit.actor`; log the resolver `source` tier for 3 days | <60% of mismatched attributions come from the explicit/env tiers (root cause is elsewhere) | 1–2 days |
| O2-S2 | Hook-injected run id: PreToolUse appends `--run <session>:<agent_id|main>` to lore Bash commands via `updatedInput`, stripping any model-supplied one; new `run_id` column | Automate | 1 main + 3 concurrent subagents, 10 evidence writes each; count `run_id` distribution | <95% of subagent writes with a correct, distinct `run_id`, or ≥1 cross-run mix-up | 2–4 days |
| O2-S3 | Read-time reverse lookup `lore who <write>`: align audit rows with local Claude Code transcripts (incl. subagent transcripts) by timestamp + command text, with a confidence. Write path untouched; no identity. | Assist | Match 50 random writes from the last 7 days | <90% unique match, or >10% with no transcript | 1–2 days |
| O2-S4 | Separate "claimed" from "attested": `--by` survives as `claimed_as`; every surface prints `attested: <run|unattested> · claimed: <name>`, attested defaulting to `unattested`; loud warning when `$LORE_ACTOR` disagrees with the session-derived name. No identity. | Defaults | Replay the "accused the wrong agent" scenario to 3 independent agents with the new format | >1 agent still holds the `claimed` name to account as if attested | hours–1 day |
| O2-S5 | Short-lived signed run token (workload-identity / OIDC style): SubagentStart signs `{session, agent_id, parent, exp}` with a key in a local file (not an env var); PreToolUse injects it; lore verifies and records `run_id` + `parent_run`; HTTP callers bind runs to existing `api_keys`. (Borrow: GitHub Actions OIDC `run_id`/`job` claims; CloudTrail `sourceIdentity`) | Borrow | Adversarial: a subagent replays another run's or an expired token | ≥1 impersonation or replay accepted, or verification adds >50 ms p95 per write | 1–2 weeks |
| O2-S6 | Subagents never write lore; they return results and the main thread writes, tagged `delegated_from: <agent_id>`, so `session_id` = run by construction. No identity. | Absurd | One autopilot run: share of writes issued by subagents, and main-thread token cost if forbidden | Subagent writes >30%, main-thread tokens +25%, or any evidence lost | hours |

Exposed constraint (S6): nobody has measured what share or value of lore writes come from subagents — and today it cannot be measured, because nothing records which writes are a subagent's.

### O3 — collecting a run's outputs back

| # | Solution | Axis | Smallest disproving experiment | Kill condition | Cost |
|---|---|---|---|---|---|
| O3-S1 | Runs own no branch: a subagent returns a `git format-patch` attached as evidence; the orchestrator applies it. No branch → no orphan. No identity. | Remove | 5 real tasks, patch-only | Any new ref/worktree appears anyway, or ≥2/5 patches fail to apply | template change only |

No identity. | Automate | Read-only sweep of the current worktrees/branches vs a manual `git branch -a` + `git log main..`; replay incident (a)'s orphan branch | ≥1 ref with unmerged commits missed, or ≥1 live worktree classified deletable (zero tolerance) | one command |
| O3-S3 | Dispatch manifest + receipt: the orchestrator records expected outputs at dispatch; the subagent must return a structured receipt (head sha, branch, evidence ids); lore diffs receipt vs git | Assist | 10 dispatches | Receipt mismatch ≥20%, or orchestrator proceeds past a shown diff ≥2 times | schema + command |
| O3-S4 | Provenance by default: `commit-msg` adds `Lore-Task: <slug>` in claimed worktrees; `lore merge` guarantees a slug on merge commits; branches default to `lore/<slug>`. No identity. | Defaults | Next ≥10 tasks with the new defaults | <95% of tasks discoverable by `lore assess`, or ≥1 slug-less merge reaches main | hook + command |
| O3-S5 | Per-run output manifest (provenance attestation): opened at SubagentStart keyed by `agent_id`; PreToolUse/PostToolUse record refs produced by `git checkout -b` / `worktree add` / `commit`; a batch completes only when every manifest item is merged or explicitly abandoned. (Borrow: SLSA provenance, in-toto links, CI artifact manifests) | Borrow | 3 subagents create branches by direct command, `bash -c`, and a script file | Manifest coverage <100% (validation ledger F5 already predicts the script-file path escapes), or SubagentStop input lacks `agent_id` | registry (highest) |

Exposed constraint (S6, S5): telling "mine" from "a peer's" loops back to identity; and command matching is a deny-list — an unmatched path silently drops out and then certifies "all collected" without evidence.

### O4 — learning which setup works (⚠️ harm unevidenced; not eligible for selection)

Measured constraint from the O4 subagent (not re-verified): a 2-week window holds ~800 evidence rows at ~4% failure; at 80% power / α 0.05 the minimum detectable change is ~2.7 points (4% → ~1.3%); judgment overrides run ~67/week. Passive observation can only see large effects. Of 40 human overrides of the review judge, 38 record no reason.

| # | Solution | Axis | Smallest disproving experiment | Kill condition | Cost |
|---|---|---|---|---|---|
| O4-S1 | Ablate one norm fragment per time window for one agent type; compare windows. No identity. | Remove | Read-only power calculation over the last 14 weeks; count other config commits per 14-day window | MDE >3 points, or >80% of windows contain >2 other config commits | near zero |
| O4-S2 | Per-run composition manifest (fragment ids + content hashes, skills, model, parent) joined to evidence pass/fail, assessment scores, gate denials | Automate | 1 week on lore-implementer | Manifest coverage <90%, or <2 distinct fragment sets within one agent type in a week (nothing to compare) | depends on O2 |
| O4-S3 | Every commit touching agent-setup assets gets an automatic before/after report (failure rate, override rate, gate denials per session, with intervals) — interrupted time series. No identity. | Assist | Backfill the ~117 historical commits | <5% of changes with an interval excluding 0 | read-only |
| O4-S4 | Version-key every prompt-bearing component (generalise `judge_prompt_version`) and never pool statistics across versions; require an override reason | Defaults | Existing sample: v2 vs v3 override rate; re-run at v3 n ≥ 300 | Intervals still overlap at n ≥ 300, or >50% of override reasons are judge noise | moderate |
| O4-S5 | Offline eval set: fixed historical tasks replayed in a throwaway corpus under two setups, k runs each, tests as oracle. (Borrow: MLflow runs, promptfoo / OpenAI Evals / Langfuse dataset experiments, GrowthBook / Statsig assignment) No identity. | Borrow | 10 tasks × 3 runs under one setup | Same-setup pass agreement <70%, or one eval round >20% of a week's normal token use | high tokens |
| O4-S6 | Setups evolve themselves: random fragment add/remove per subagent start, keep what scores better | Absurd | 2 weeks on the explorer type | Gate denials per session +25%, or ≥1 hard-constraint violation (read-only, live-corpus write) | needs O4-S2 |

Exposed constraint (S6): some norms are load-bearing safety rules; any setup comparison needs a declared "never ablate" set.

## Branch selection

Anchored scales (mode-opportunity): evidence strength, outcome leverage, disproof cost; rank by mean, ties broken by disproof cost.

| Opportunity | Evidence | Leverage | Disproof cost | Mean |
|---|---|---|---|---|
| O2 | 5 — E1 ×4 | 5 — the outcome IS run attribution of writes | 4 — O2-S4/S6/S1 in hours; O2-S2 days (partly done in the ledger spike) | **4.67** |
| O1 | 5 — E1 ×3 | 3 — claims are one of the three counted write kinds | 5 — claim-history replay, hours | 4.33 |
| O3 | 4 — recorded, not re-measured | 2 — git artifacts, not counted writes | 5 — read-only sweep, hours | 3.67 |
| O4 | 2 — gap E1, harm E6 | 1 — consumes run identity, does not produce it | 5 — backfill, hours | 2.67 (ineligible: harm unevidenced) |

**Recommended — O2 (attribution).** Carry all six O2 solutions into `validate`, in assumption-map order (cheapest kill first): O2-S6 (what share of writes do subagents issue — if small, the problem shrinks) and O2-S4 (does honest labelling alone stop wrong accusations) and O2-S1 (replay: is free-text attribution the main source of mismatch) — all hours; then the MCP half of O2-S2 (A5 in the ledger, the open feasibility gap); then O2-S5's adversarial test.

**Alternative — O1 (takeover).** Promote it if O2's attestation path is refuted (for example MCP or non-Claude callers cannot be attested). Its no-identity solutions (O1-S1 Remove, O1-S5 fencing token, O1-S2 Defaults) then become the fallback. Note: every measured same-task takeover so far (2 of 2, 2026-08-11) was cross-session, which O1-S2 alone would have caught — the ledger's refutation of the session-id-only fix concerns subagent concurrency, which today's data cannot observe at all.

**Not recommended now:**
- **O3** — real, but low leverage on this outcome. Its strongest solutions (O3-S2 reconcile sweep, O3-S4 provenance defaults) need no run identity and can proceed independently of this tree. Reopen as a tree of its own on the next orphan-branch or worktree-loss incident, or when #106 is scheduled.
- **O4** — harm from guessing is unevidenced (E6), and it consumes run identity rather than producing it. Reopen when O4-S3's backfill (read-only, hours) shows any setup change with an interval excluding zero, or once O2 has landed run ids.

## Cross-cutting concerns

- Privacy: O2-S3 reads local session transcripts — sensitive, local-only, and absent on other machines; O2-S5 and any run record must not persist `transcript_path`, and worktree paths conflict with SPEC-025's exclusion of local paths from the corpus (ledger).
- Harm: O4-S6 can randomly remove safety norms — any setup experiment needs a "never ablate" set. O3-S6 and O1-S1 can block or mislabel a concurrent peer; both must fail with a fix hint, never silently.
- Accountability: takeover must remain possible for humans, made explicit and recorded (O1-S1, O1-S4).
