| concurrency_safety | pass | Each store write is a single-row UPDATE on the PK (SQLite and Turso) or a single Map.set (in-memory), so no write can be partly applied. Two concurrent registers of the same main run, such as a resume racing a startup, resolve as last writer wins. That is the intended 'newest register wins' semantics, not a lost write. The insertRun then recordRunAddress pair is not atomic, but insertRun ignores the address, so interleaving cannot leave a stale first-wins value. The holder lookup is read-only.
