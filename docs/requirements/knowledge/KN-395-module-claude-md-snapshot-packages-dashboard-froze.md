# Module: @lore/dashboard

## Purpose

Local-development web UI for browsing and editing the Lore corpus. Vite + React 19 + TypeScript + Tailwind v4 + shadcn/ui. Read views per SPEC-015 (search / tree / detail; list moved to `/library`, see below) plus the SPEC-022 write surface: create, in-place markdown editing (CodeMirror 6 + split preview), status transitions, link management, version history tab, optimistic-concurrency conflict resolution. SPEC-027 hardening added soft delete (confirmation-gated) and per-version restore (append-only), both cookie-gated. Auth is the SPEC-016 cookie bootstrap.

**Home (`/`) is the resolved living PRD, not a doc list (SPEC-033 F2, PRD-001 §13.5).** The corpus's single PRD document is rendered via `ResolvedPrdBody` — its MDX placeholders (`ChildrenOf`/`RecentDecisions`/`ActivePlans`/`RelatedOf`/`ModuleTree`/`HealthStats`/`Embed`) are spliced in as typed React components (`splitContentByPlaceholders`, `src/lib/resolved-content.ts`), never as raw tag text or `dangerouslySetInnerHTML`. Side panels (`PendingPanel`, `ActivePlansPanel`, `LoopPanel`) surface the feedback loop: pending-review queue with AI judgment badges, active plans (per-plan readiness via `GET /api/ready/:planIdOrSlug`, landed SPEC-037 D1 — `ActivePlansPanel` fetches its own row via `apiGetReadyReport`, reading `.value.records`, no stand-in — a same-named `apiGetReady` once typed this route's response as a flat `ReadyRecord[]` instead of the real `{records, sessions, anchor_conflicts}` object the server has returned since SPEC-042, breaking this panel and `PlanExecution` at render time; deleted as a regression fix, `task-fix-live-spec-042-regression-apigetready-types-api-ready`), and calibration stats + audit-verify status. The original SPEC-015 doc-browsing + create UX (type filter chips, `NewDocModal`) moved to `/library` (`routes/library.tsx`) — no functionality was dropped, only relocated off the PRD-projection surface SPEC-033 claims for `/`.

**Review queues merge draft + in-review (2026-07-26 dogfood ISSUE-008, ADR `adr-dashboard-review-queues-include-in-review-docs-ahead-of`).** `src/lib/review-queue.ts::fetchReviewQueueRows` is the single queue source for BOTH home `PendingPanel` and `/pending` `TriageQueue`: it merges `GET /api/review/pending` (drafts — server/CLI semantics untouched) with `apiList({status:"in-review"})` (+ per-row `apiGetDoc` for real `version`/`created_by`, never fabricated — a fake version would corrupt `JudgmentBadge` staleness). In-review rows sort ahead and every row renders a read-only `StatusPill`. TriageQueue's Approve is gated by `getAllowedTransitions(status)`, never assumed. `NewDocModal` defaults to `knowledge` (spec is create-blocked), and its parent field is a hand-rolled ARIA-complete combobox (`aria-activedescendant` listbox) filtering title+slug via `src/lib/parent-suggestions.ts` (reuses `@lore/core` `isValidParentType` — no client-side parent rules) fed from the library's cached `apiList` — raw pasted slug/ULID stays submittable. `PhaseProgressPanel` dispatches on the SPEC-077 `PlanPhaseEntry` union (`source: "phase-doc" | "declared"`; api.ts byte-mirrors `phase-workflow-service.ts`): declared entries render title/task-count/evidence chips/served `ac_coverage` (never recomputed) + an `orphaned` warning badge, no checklist; empty state only when both sources are empty.

**DocDetail gains an Evidence tab + AdjudicationBar (SPEC-075, dashboard adjudication workbench).** `task`/`spec`/`plan` docs get a 4th "Evidence" tab (alongside content/history/audit) rendering `EvidenceTab` — a thin dispatcher over `GET /api/evidence-panel/:idOrSlug`'s `EvidencePanelProjection` union (`@lore/core`) onto one of three 1:1 panel subcomponents (`components/evidence/{TaskEvidencePanel,SpecAcCoveragePanel,PlanAttestationPanel}.tsx`); `prd`/`adr`/`knowledge`/`phase` docs never show the tab button at all. Any doc with `status === "in-review"` additionally renders `AdjudicationBar` in the header (same screen as the rest of the doc, R-8) — evidence-summary chips (`summarizeForAdjudicationBar`, `@lore/core`) plus approve/reject with an optional calibration note, reusing `apiApproveDoc`/`apiRejectDoc`. `JudgmentDrilldown` expands a `JudgmentBadge`-adjacent row (mounted in `TriageQueue`) into the judgment's decision/confidence/reasons/checks/blocking_questions/prompt_version. `use-triage-keyboard.ts` (j/k select, a/x/e/o adjudicate/reject-flow/expand/open, suppressed on editable focus) drives `TriageQueue`; `use-route-telemetry.ts` fires one `POST /api/dashboard/telemetry/route-view` per navigation from `__root.tsx` (fire-and-forget, never throws).

**`/execution` is the SPEC-077 dashboard execution read surface (PRD §21 F3)** — the first reachable UI onto execution state that previously required the CLI. A top-nav "Execution" link (`__root.tsx`) routes to `ExecutionPage` (`routes/execution.tsx`, thin router wrapper; `?plan=<idOrSlug>` search param is the SSOT for plan selection, defaulting to the most-recently-active plan when absent — never a `useState`). `ExecutionPage` owns ALL data fetching for the page (two `useQuery` calls per selected plan: `apiGetReadyReport` and `apiGetPhaseStatus`, both `src/lib/api.ts`) and renders four pure-props panels: `ReadyTaskList` (one row per `ReadyReport.records[]`, tri-state claim badge — fresh w/ `claim_ttl_minutes − age_minutes` countdown clamped at 0, stale w/ literal "stale" label, or none), `SessionsPanel` (one row per derived `(by, machine, worktree)` session), `AnchorConflictsPanel` (one row per SPEC-042 D7 anchor-overlap advisory), and `PhaseProgressPanel` (one scorecard per `GET /api/phase-status/:planIdOrSlug` phase — the T1 route, a thin pipe over `PhaseWorkflowService.planPhaseStatus`). `PhaseProgressPanel`'s `PhaseScorecard` client type (`api.ts`) mirrors the server's `PhaseScorecard`/`PhaseScorecardAcSummary`/`PhaseScorecardChecklistSummary`/`PhaseScorecardChecklistItem` (`packages/lore/src/service/phase-workflow-service.ts`) field-for-field — `phase_title` (not `name`), aggregate `checklist` counts plus a separate `checklist_items[]` array (`{id, statement, state, trust}`), no `dropped_item_names` field (dropped names are derived client-side from `checklist_items` entries whose `state === "dropped"`, `PhaseProgressPanel.tsx`'s `droppedItemNames` helper). A prior version of this client type was authored ahead of the real T1 route and never reconciled, crashing the entire `/execution` page for any plan with ≥1 phase (fixed: `task-fix-spec-077-t2-client-shape-drift-phasescorecard-client`). Per-task evidence timelines are reached by clicking a `ReadyTaskList` row (navigates to `/docs/$id`, landing on the pre-existing SPEC-075 Evidence tab) — zero-step navigation, never a duplicated timeline component. Execution verbs (claim/release/evidence) stay CLI-only; this surface is strictly read-only.

## Local-dev topology

```
Terminal A          Terminal B                   Browser
──────────          ──────────                   ───────
bun run dev         bun run --filter             http://localhost:5173
→ lore serve          '@lore/dashboard' dev          │
→ :8787             → vite :5173 ◄──────────────────┘
                       └── proxy /api/* ──► localhost:8787
```

Two-process model intentional. `vite.config.ts` sets `server.proxy: { "/api": "http://localhost:8787" }` so the browser sees one origin (no CORS).

## Key Invariants

- **Writes only via `/api/dashboard/*` (SPEC-022 + SPEC-027).** All mutations go through the eight cookie-gated dashboard endpoints (`src/api/mutations.ts`): create, PATCH, approve, reject, link create/delete, DELETE doc (`?confirm=true` required), POST restore. `src/lib/api.ts` stays read-only. Optimistic concurrency: PATCH sends `If-Match: <version>` — including status transitions (SPEC-027 AC-DH-2); 409 surfaces the ConflictModal; force overwrite = no `If-Match` + `X-Force-Overwrite: 1`. Status transitions render from `getAllowedTransitions()` in `@lore/core` — never hardcode the lifecycle.
- **Edit-session state must not survive doc navigation.** `docs.$id.tsx` mounts `<DocDetail>` with `key={doc.id}` so a warm TanStack Query cache hit cannot reuse a component instance carrying another doc's unsaved editor state (SPEC-027 AC-DH-1 — removing the key reintroduces a cross-document write bug pinned by `DocDetail.write.test.tsx`). Save/Cancel must clear the draft debounce timer before `clearDraft` (AC-DH-3).
- **No login UI.** Dashboard never asks the user for credentials. `lore dashboard` (SPEC-016) creates `.lore/local-key` if missing, spawns Vite with the raw key as `VITE_LORE_BOOTSTRAP_TOKEN`, and a dev-only Vite plugin inlines it into `index.html` as `window.__LORE_BOOTSTRAP_TOKEN__`. `src/lib/bootstrap.ts::bootstrapAuthIfNeeded()` POSTs the token to `/api/auth/local-bootstrap`, receives an HttpOnly `lore_sid` cookie, and deletes the window global. Every subsequent `fetch` carries `credentials: "include"` — cookie does the auth.
- **Depends on `@lore/core` only.** `packages/dashboard/package.json` MUST NOT depend on `@lore/lore`. All server interaction goes through HTTP. Boundary check: `grep -r 'from "@lore/lore"' src/ → 0`.
- **No server-side modules in `src/`.** No `bun:sqlite`, `child_process`, `node:fs`, or any other Node-side built-in. Dashboard is a browser app. Boundary check: `grep -rE 'bun:sqlite|child_process|node:fs' src/ → 0`.
- **TanStack Router file-routing.** Five route files under `src/routes/`. `routeTree.gen.ts` is git-ignored and regenerated by the Vite plugin on dev start + the `prebuild` script. Don't commit it.
- **All client state is server state (TanStack Query) + URL state (router).** No Zustand / Jotai / Redux even "to set up". When state appears stateful, ask: is this query cache or a query param? It should be one of those. `/library`'s type/status/tag filters (SPEC-036 §1 D2) are the reference example: `validateSearch: librarySearchSchema` (`src/lib/library-search.ts`) + `Route.useSearch()` — NOT `useState` — so filters survive reload/back/forward (a prior version of this route used `useState`, which this spec fixed as a violation of this exact invariant).

## Patterns

- **`src/lib/api.ts`** — typed fetch wrapper returning `Result<T, ApiError>`. 5-second `AbortController` timeout. Normalises errors to `{ code, message }`. All route handlers call this; nothing else touches `fetch`. SPEC-033 F1/F2 added `apiGetJudgments`, `apiGetAuditForDoc`, `apiGetAuditVerify`, `apiGetCalibrationStats`, `apiGetPendingReview` (feedback-loop reads; response shapes mirror their `packages/lore/src/service/*.ts` origin types exactly, documented inline per-function). SPEC-075 added `apiGetEvidencePanel` + the shared `evidencePanelQueryKey(idOrSlug)` helper (so `EvidenceTab`'s own fetch and `DocDetail`'s header-level `AdjudicationBarSection` fetch resolve to the same TanStack Query cache entry — one network request, not two).
- **`src/api/mutations.ts`'s `apiPostRouteView` (SPEC-075 D4) is the one deliberate exception to "every write helper throws `DashboardApiError`/`ConflictError`"** — it is fire-and-forget: network errors, timeouts, and non-2xx responses are ALL silently swallowed (the PRD-documented telemetry exception), because a broken observability ping must never surface a toast or break navigation. `use-route-telemetry.ts` calls it once per `useRouterState` pathname change (a `useRef` guard prevents a same-pathname re-render or React StrictMode's dev double-invoke from double-firing).
- **`JudgmentBadge` (`src/components/judgment-badge.tsx`) is the single shared review-judgment badge** — consumed by F2's `PendingPanel` (home page) and F3's triage queue page. Renders `"{decision} {confidence.toFixed(2)}"` / `"escalate +NQ"` / `"unreviewed"`, with a `(stale)` suffix + outline-variant downgrade when `judgment.doc_version < docVersion`. Mirrors the CLI's `formatJudgmentBadge` (`packages/lore/src/adapters/cli/utils.ts`) semantics — don't reimplement the staleness/label rule a third way.
- **`Breadcrumb` (`src/components/Breadcrumb.tsx`) is the single ancestor-chain trail** (SPEC-036 §1 D1) — mounted at the top of `DocDetail.tsx`, above the title block (the bottom navigation footer still shows only the direct parent, unchanged). Renders `Home / <ancestors…> / <current title>` from `DocWithNavigation.navigation.ancestors` (root-first `DocSummary[]`, `src/lib/api.ts`); collapses >3 ancestors into one non-interactive `…` crumb (full titles in its `title` attribute), always keeping root + direct parent visible. `onNavigate`/`onHome` are optional callbacks (same safe-if-absent convention as `DocCard`'s `onClick?.()`) — `routes/docs.$id.tsx` wires both to real navigation; only unit tests omit them.
- **`TYPE_ACCENT` (`src/lib/type-accent.ts`) is the single per-`DocType` accent-color source** (SPEC-036 §1 D3) — one `border-l-<hue>-600 dark:border-l-<hue>-500` class pair per type, consumed by both `DocCard`'s left border and `DocDetail`'s header border so a type always renders the identical hue on both surfaces. The shade pairing (600 light / 500 dark, NOT the more common "500 light / 400 dark") was chosen because it's the pairing that actually clears WCAG 1.4.11 (>=3:1 non-text contrast) against this project's real shadcn `--card` tokens in BOTH themes — verified by converting the installed `tailwindcss` v4 theme.css's exact `oklch()` triples to sRGB and computing WCAG relative luminance; the naive 500/400 pairing fails in light mode for most hues. Accent color is always supplementary to a text type-badge — never the only signal.
- **`formatTypeMetaLabel` (`src/lib/type-meta-label.ts`) is the single per-type meta-row TEXT deriver** (SPEC-036 §1 D3) — `DocCard` and `DocDetail` both call it (on `doc.meta`, a `DocSummary`-only field) and wrap the result in their own badge/layout; neither hand-rolls the projection independently. The `task` variant's "nothing when neither claimed nor evidenced" rule mirrors the CLI's `formatWorkflowBadge` (`packages/lore/src/adapters/cli/utils.ts`) — evidence renders as exact `evidence_pass`/`evidence_fail` totals (a different FORMAT from the CLI's last-result-plus-total badge, not a different RULE about when to show anything). `isNotablePriority` (same file) gates the priority badge to `critical`/`high` only (noise budget). `DocDetail.tsx` has no `.meta` of its own on the raw `DocRecord` it receives (that projection only exists on `DocSummary` list rows) — it computes the same union client-side via `deriveTypeMeta(doc)` (`@lore/core`, browser-safe), which necessarily omits `claim_stale` (no `claimTtlMinutes` available client-side) rather than fabricating `false`.
- **TanStack Query hooks** — `useSuspenseQuery` + `<Suspense>` boundaries for loading; `<Skeleton/>` from shadcn for shimmer.
- **Component primitives** — shadcn under `src/components/ui/` (button / card / input / table / badge / scroll-area / separator / skeleton / dropdown-menu / sonner). Compose into feature components (`DocCard`, `DocDetail`, etc.) under `src/components/`.
- **Theme** — `useTheme()` reads localStorage `theme` and applies `dark` class to `documentElement`. Tri-state: light / dark / system. **Tailwind v4's `dark:` variant MUST stay overridden to class-based** in `src/index.css` (`@custom-variant dark (&:where(.dark, .dark *));`): v4 defaults `dark:` to the `prefers-color-scheme` media query, so without the override an OS-dark machine fires `dark:prose-invert` inside the app's LIGHT theme — near-white prose on white background, ≈1.4:1 contrast (2026-07-26 dogfood ISSUE-009). Pinned by `tests/unit/lib/index-css-dark-variant.test.ts`.
- **SPEC-075 evidence-panel projection consumers never re-derive coverage/attestation math** — `EvidenceTab`'s 3 panel subcomponents and `AdjudicationBar`'s chip summary render numbers computed entirely in `@lore/core` (`computeAcCoverage`, `deriveAcCoverageState`, `deriveAttestationSummary`, `summarizeForAdjudicationBar`) and served verbatim by `GET /api/evidence-panel/:idOrSlug`; a component adding its own pass/fail counting would fork from the `plan-close` gate's own math (SPEC-069 `attestationFloor` shares the same core functions). `AttestationSummary.ratio === null` renders explicit "not applicable" copy in `PlanAttestationPanel` — never a fabricated "0%".
- **`use-triage-keyboard.ts`'s selection index is the one documented exception to "all client state is server/URL state"** (D5) — ephemeral row focus for j/k navigation, not data worth persisting; mirrors the editor-draft-ephemera precedent. Its suppression predicate (`isEditableTarget`, exported for direct testing) matches `input, textarea, [contenteditable="true"], .cm-editor` exactly.

- **`NewDocModal` refuses to submit `docType === "spec"` at all** (ADR `adr-newdocmodal-spec-create-cli-skill-only-authoring-disable`, `TYPES_BLOCKED_AT_CREATE`): the spec-create gate's real requirements (skeleton headings PLUS structured, oracle-verifiable ACs added via a separate `lore ac add` call) can never be satisfied by a single create-time payload, so a seeded template would only mechanically pass the gate while staying hollow. Selecting `spec` renders a visible notice naming `lore create spec` (CLI) / `/lore-design` (skill) and disables Create — both in the JSX `disabled` attribute AND inside `handleSubmit` (the same belt-and-braces shape as the `isPending` guard, since a stray form `submit` event bypasses a button's own `disabled`). No other type carries a create-time content gate, so this is scoped to `spec` only. `NewDocModal.test.tsx` covers it; extend `TYPES_BLOCKED_AT_CREATE` (not a new mechanism) if another type gains a create-time content gate.
- `tests/e2e/global-setup.ts` fails loud on two independent guards, not just `waitFor200` optimism: `assertPortFree` raw-TCP-probes 8787/5173 BEFORE spawning anything (never auto-kills a squatter — it might be someone's live corpus server), and `assertServerIsOurs` bearer-authenticates `/api/auth/me` with the just-created `dashboard-local` key after `lore serve` starts, since that key's hash exists in exactly one `api_keys` table (a squatter answers 401, not 200). Both guards exist because a stale `lore dashboard` process once squatted 8787, `/health` answered 200 anyway, and the whole write-path suite ran against — and polluted — the real team corpus.
- `tests/e2e/execution.pw.ts` (SPEC-077, AC-077-5) — nav-entry-to-`/execution` roundtrip, plan selection via `?plan`, all four S2 panels asserted against a seeded fixture (one plan promoted to `active`, two tasks sharing one declared file anchor with one fresh claim producing both the ready-task claim badge and the one session, the other's un-claimed overlapping anchor producing the one anchor-conflict row, and one `phase`-typed doc), and the ready-task-row-click → `/docs/$id` → Evidence-tab-visible drilldown. Fixture seeded by `tests/e2e/seed-execution-fixture.ts`, a separate `bun` process calling `CorpusService`/`TaskWorkflowService` directly against the shared throwaway corpus's SQLite file (`seed-judgment.ts`'s pattern) — needed because a plan reaching `active`, a `phase` doc (migration-created only per the CLI's `VALID_TYPES` allowlist), and a fresh claim are each unreachable through the CLI/dashboard-UI surfaces alone.
