## Overview/Goal

Answer evaluation questions B (delivery efficiency), C (delivery quality), D (concurrency) and E (unattended autonomy) from facts lore already records: task claims and completions, integrate attempts, main-red regression records, issues, runs and autonomy decisions (OST O3, O4; benchmark rows 1, 2, 4 table stakes and row 13 gap). DORA's five measures are mapped onto lore's units of work, and the concurrency ledger shows whether more parallel agents land more work or only collide.

Staged requirements R-39, R-40, R-41. Baseline: leaf `baseline-measure-delivery` (proposed rules below), reading BR-1245 (what a landing and a lost race are). Depends on S-A (envelope).

## Scope

| Metric | Question | Definition | Source |
|---|---|---|---|
| `delivery.lead_time_median` | B | Median time from a task's first claim to its completion after landing, over tasks completed in the window; tasks completed without a claim are excluded and counted | claim and archive versions |
| `delivery.landings_per_day` | B | Landings (integrate merge commits on main) per calendar day (UTC) in the window | main's git history (BR-1394, BR-1420) |
| `delivery.change_fail_rate` | C | Landings in the window followed within 7 days (inclusive) by a local main-red record whose commit range includes the landing ; a landing with fewer than 7 days to the reference point (the window end if it is in the past, else now) is pending, excluded and counted | main's git history + local main-red records (BR-1420, BR-1412, BR-1395) |
| `delivery.rework_rate` | C | Tasks completed in the window that resolve (by `resolves` link) an issue naming a file path a landing changed within the 14 days before the issue was filed, over all tasks completed | tasks, `resolves` links, issues (injectable port), files changed by landings in main's git history, however old (BR-1396) |
| `delivery.recovery_median` | C | Median time from a local main-red record to its recorded green time, over records that turned green; open records reported beside it as open count and oldest age, not in the median | local main-red records (BR-1414) |
| `concurrency.parallel_runs` | D | Live runs per hour, a never-ended run live only until its last attributed write, or its start if it wrote nothing: median and max, with the number of never-ended runs in the window reported beside them (BR-1397) | runs |
| `concurrency.conflict_rate`, `.lost_race_rate` | D | Attempts with outcome conflict / lost_race over all attempts, every outcome kind (landed, lost_race, conflict, floor_failed, snapshot_migrate_failed) in the denominator | integrate attempt ledger |
| `autonomy.decided_without_person_share`, `.person_wait_median` | E | verdict auto/refuse + channel machine = decided by lore; escalate answered by the next human-tty row for the same class, subject, version; superseded, milestone, outcome and threshold rows excluded and counted | decision record |

Landings are integrate merge commits on main, read from main's history, which is never rewritten (BR-1420), so lead time, landings per day, change fail rate and rework can be re-read for any past window. The integration attempt history keeps every attempt younger than 30 days for every branch, each with start time, outcome and per-step exit codes (BR-1419); it feeds only the conflict and lost-race shares, which report no_data with cause source_absent for any part of a window starting more than 30 days ago (BR-1415).

## Out of scope

- Trends and colours (S-E). Per-person breakdowns (non-goal, trap row 20). Activity counts such as commits or lines (trap row 22).
- Keeping attempt history longer than 30 days: only the attempt shares read it, and their older trend buckets are no_data (BR-1415); every landing-based metric reads main's permanent history instead.

## Design Decisions

| # | Decision | Chosen | Rejected and why |
|---|---|---|---|
| C-D1 | "Deploy" unit | One integrate landing | A plan close (too coarse: <10 closed plans per window, OST O3-S2 kill) ; a git commit on main (merge commits double-count) |
| C-D2 | Lead time start | First claim of the task | Task creation (a task can wait in the ready set for weeks; that is queueing, not delivery) |
| C-D3 | Change-fail window | 7 days inclusive; a landing with fewer than 7 days to the reference point (the window end when it is in the past, else now) is pending (BR-1395) | 14 days (the per-plan `checks stats --quality` window; landings are finer and 14 would attribute unrelated reds); counting undecided landings as not failed (biases the rate low); measuring pending from now for a past window (a past window's figure would keep changing) |
| C-D4 | Parallelism source | Live runs from the run registry | Claude Code OpenTelemetry `session.count` (needs an external collector; Lore is one binary - OST O4-S2 kill) |
| C-D5 | Throttling on conflict rate | Not built | OST O4-S3 (absurd axis): only if phase 1 shows r >= 0.3 between parallel runs and conflict rate, and then as a separate spec |
| C-D10 | How an issue is tied to landed work (review rev-3) | A file path the issue names was changed by a landing within the 14 days before filing | An explicit link from the issue to a task (agents write it, so it grades itself: B-D13); the resolves link alone (ties the fix, not the cause) |
| C-D11 | Open main-red records in recovery | Reported beside the median as open count and oldest age; median over closed records | Right-censored median (a survival estimate a reader cannot check by hand); dropping open records (hides the longest outages) |
| C-D13 | Where landings come from (review rev5-3) | Main's git history: the integrate merge commits, never rewritten (BR-1420); the 30-day ledger feeds only the attempt shares | Landings from the attempt ledger (old windows would vanish after 30 days, breaking re-reads, change fail rate and rework); keeping the ledger forever (a second, unbounded copy of what git already keeps) |
| C-D12 | Attempt history too short for a window (review rev4-3) | Fix the source: the ledger keeps every attempt younger than 30 days, with start time and step exit codes always recorded (BR-1419) | Reporting truncated branches and a `possible undercount` reason (a permanent disclaimer over a fixable source); a conditional capture decided by an experiment (an input contract that depends on an experiment's outcome) |
| C-D6 | Where main red is read from (S3 eng 1) | A local main-red record written by the milestone review at detection (BR-1412); issues read through an injectable port in tests | Reading GitHub issues by fingerprint over the network (unavailable offline, not testable without a fixture port) |
| C-D7 | Scope (S3 PS2) | Dropped attempts_per_landing and queue_wait | Keeping them (no question needs them in v1; each adds a criterion and anchors) |
| C-D8 | Never-ended runs (S3 eng 8) | Live until last attributed write | Live until now (113 of 755 runs never ended would inflate parallelism) |
| C-D9 | Goodhart (S3 DA1) | rework_rate carries the guard figures of S-B (BR-1389); asserted by AC-DC-3 | — |

Falsifier literals implementers must keep: `FAIL_WINDOW_DAYS = 7` and `LANDING_COMMIT_PATTERN = /^merge\(/` in `packages/lore/src/service/metrics/delivery-metrics.ts`; `"lost_race"` in `packages/lore/src/service/metrics/concurrency-metrics.ts`; `KEEP_ATTEMPTS_DAYS = 30` in `packages/lore/src/service/integrate-attempt-ledger.ts`; `REWORK_LOOKBACK_DAYS = 14` in `packages/lore/src/service/metrics/delivery-metrics.ts`; `recordMainRed(` in `packages/lore/src/service/milestone-review-service.ts`; `"decided_by_lore"` in `packages/lore/src/service/metrics/autonomy-metrics.ts`; `"resolves"` in `packages/lore/src/service/metrics/delivery-metrics.ts`.
