# Evidence labels and reds are honest

## Goal

Every evidence row's trust label matches how it was produced, and a red recorded as proof of a failing test proves a TEST failed: an inconclusive falsify row is no longer labelled `runner`; a falsifier cannot declare or replay an expected exit code of 0; a script criterion cannot be declared with a pipe that hands the check's exit code to another command; a captured red for a test/e2e check must show a runner summary with a failed test; exit codes 126/127 are never a red, on the capture path or the falsify path. Issues #48, #43, #19, #53.

## Why now (measured 2026-10-12)

- #48: `service/verify-runner-service.ts:1910-1921` writes the green-control-failed row with `result: "inconclusive"`, `capture_source: "runner"` and no `attestation` — the exact false label root CLAUDE.md's North Star names. It is the only one of the file's three evidence writes (`:1239`, `:1910`, `:2002`) without an attestation. Tests pin it: `tests/unit/service/attested-red.test.ts:684`, `tests/integration/cli/verify-falsify-green-control.test.ts:350,:519`, `tests/unit/service/falsifier-dep-materialization.test.ts:1310`; `packages/core/src/task-workflow.test.ts:552` pins `CAPTURE_SOURCES` by `toEqual`. `CAPTURE_SOURCES` (`packages/core/src/task-workflow.ts:163`) has only `runner | self-report`; `lore status` buckets rows as `runner` vs everything else (`commands/status.ts:738`, `:920-925`); `commands/assess.ts:447` and `commands/verify.ts:559` render the label; `phase-workflow-service.ts:729` has its own `appendEvidenceEntry` twin.
- #43: `acFalsifierSchema.expected_exit_code` (`packages/core/src/acceptance.ts:167-171`) is `z.number().int()`; `ac add --falsifier-exit-code 0` exits 0, and `verify --falsify` then records `result: expected-fail` with an attestation whose exit code is 0 for a check that passed. Measured in the live corpus (read-only query): 53 stored falsifiers, 0 outside 1..255.
- #19: `lore ac add|set` stores `false | tail -1 && echo PASS` silently (7 such criteria were stored and hand-corrected). The detector already exists for self-reported evidence: `commandHasUnsafePipe` (`adapters/cli/evidence-precheck.ts:907`). Run over the 907 stored test/e2e criterion commands in `docs/requirements/spec/` it flags 31 — all 31 are the SAFE `out=$(...); ec=$?; ... | grep -q ...` form (exit code captured before the pipe); 0 are masking today. Criteria also reach the store through document create, import and restore; `service/ac-write-chokepoint.ts` (`admitAcWrite`, paths `ac-verb | create | restore | import | wholesale`) is the one place every sanctioned path passes.
- #53: `adapters/evidence-capture.ts:430-443` accepts any non-zero exit as `fail`/`expected-fail`; measured three times in one session (jq error, grep syntax error, failed `cd` in 4 ms), each recorded as a runner-attested red that clears `lore done`'s red-first floor (which accepts `expected-fail` and `fail` rows alike). Tests pin it: `tests/unit/adapters/evidence-capture-window.test.ts:252-257` (exit 127 accepted as `fail`), `tests/unit/adapters/evidence-capture-attestation.test.ts:342-371` (a captured `fail` with no runner summary). `_runFalsifier` (`verify-runner-service.ts:1766+`) has no `findDiscoveryRefusal` call (`attestation-completeness.ts:1257`), unlike plain verify (`:1157`), and accepts an observed 126/127 as a matching red.

## Scope

- `CAPTURE_SOURCES` gains `runner-unattested`; the green-control-failed row uses it; every reader keeps treating only `runner` as runner-captured; `lore status`, `lore assess` and `lore verify` render a third, distinct label.
- `ac-write-chokepoint.ts` refuses, for every criterion ADDED or whose command / oracle / mode / falsifier CHANGED, on every sanctioned path (ac add/set, create, import, restore): a falsifier `expected_exit_code` outside 1..255, and an unsafe-piped command under any script oracle except `other` (`other` gets an advisory). Unchanged stored criteria are not re-checked.
- `commandHasUnsafePipe` moves to a pure `@lore/core` module; `evidence-precheck.ts` and the chokepoint import the same function.
- `lore verify --falsify` refuses a stored out-of-range falsifier before running anything.
- Captured `fail`/`expected-fail` for test/e2e needs a recognised runner summary with >= 1 failed case IN THE STORED TAIL; exit 126/127 is refused for every captured `fail`/`expected-fail`; one precheck function both the CLI (`commands/evidence.ts`) and MCP (`lore_evidence_add`, `tools.ts:2267-2285`) call; `captureOracleCommand` is unchanged.
- `_runFalsifier` records a mutated run that shows a runner discovery refusal, or ends 126/127, as `inconclusive` / `runner-unattested`, never `expected-fail`.
- Re-baselined pinned tests: the five #48 files above, `evidence-capture-window.test.ts:252-257`, `evidence-capture-attestation.test.ts:342-371`, `capture-source-required.test.ts`, `adapters/capture-source-visibility.test.ts`.

## Out of scope

- Tightening `acFalsifierSchema` (D4).
- Re-checking already-stored criteria; only a write that adds a criterion or changes its `command`, `oracle`, `mode` or falsifier is checked (D7).
- Plain `lore verify` `fail` rows: their command is the declared criterion command, so a broken command is a criterion defect; BR-176 already covers its discovery refusal.
- Playwright and other runners' summaries: only the formats in `RUNNER_SUMMARY_FORMATS_DESCRIPTION` (vitest, bun test) are recognised; a captured red from another runner is refused naming those formats (R3 in the plan).
- Historical rows already labelled `runner` without attestation are not rewritten (the evidence log is append-only); `lore status` keeps counting them as before.

## Design Decisions

- **D1 — a third label, `runner-unattested`, for a row lore itself ran but did not attest.** Rejected: `self-report` (false — no caller typed the result; lore ran the control); omitting `capture_source` (readers map an absent value to `self-report`, the same lie); attaching an `attestation` (promises a mutation was applied and compared — AC-FR-11 forbids it).
- **D2 — readers stay closed on `runner`.** Every `capture_source === "runner"` check (e.g. `task-workflow-service.ts:1043`, `:1647`, `:2404`) is unchanged, so `runner-unattested` never counts as runner-captured or attested, and a `result: "pass"` row labelled `runner-unattested` never satisfies `lore done`'s attested-pass floor. Rendering is injective: `lore status --json` adds `capture_source_runner_unattested_count` (with an `--enumerate` entry), and `capture_source_runner_count` + `capture_source_self_report_count` + the new count equals the total row count; assess and verify rendering print a third label. A row labelled `runner-unattested` that carries an `attestation` is refused (VALIDATION_ERROR) by BOTH `appendEvidenceEntry` writers — `TaskWorkflowService` and its twin in `phase-workflow-service.ts:729` (through one shared helper) — the two claims contradict.
- **D3 — criterion checks live in the AC write chokepoint, for changed criteria only.** `admitAcWrite` (`ac-write-chokepoint.ts`) runs the falsifier range check (1..255) and the pipe check (D7) on each criterion that is new or whose `command` / `oracle` / `mode` / falsifier differs from the stored one, for every `AcWritePath` (`ac-verb`, `create`, `import`, `restore`, `wholesale`); VALIDATION_ERROR, CLI exit 4, nothing written. A stored criterion left unchanged is never re-checked, so stored data stays writable around it. Rejected: checking in `AcService` only (document create / import / restore would still store a 0 or a masking pipe); a CLI-only argv check (every gate in this codebase runs in the service layer).
- **D4 — the Zod schema is not tightened.** Whole-array parsing means one stored out-of-range value would make every read of that spec's criteria fail closed. Rejected: `z.number().int().min(1).max(255)` in `acceptance.ts`.
- **D5 — `verify --falsify` refuses a stored out-of-range value before the control runs.** VALIDATION_ERROR, exit 4, executor never called, no evidence row; the message names `lore ac set <spec> <AC> --correction "<reason>" --falsifier-exit-code <n>` (the BR-1069 exit for a locked spec). Consequently an observed 0 can never be recorded as an attested red.
- **D6 — one pipe detector, in `@lore/core`.** `commandHasUnsafePipe` moves to `packages/core/src/command-pipe.ts` (pure, exported from the barrel; browser-safe, no Node import); `evidence-precheck.ts` imports it and re-exports it for existing importers; the chokepoint calls it. Rejected: a second copy in the service layer; importing the CLI adapter module from the service layer (wrong direction).
- **D7 — the pipe refusal covers every script oracle except `other` (user decision U1).** For `test`, `e2e`, `tsc`, `lint`, `build`: VALIDATION_ERROR field `command`, exit 4, naming the pipe and the POSIX pipe-free form (`f=$(mktemp); <check> > "$f" 2>&1; ec=$?; cat "$f"; [ "$ec" -eq 0 ] && grep -q <pattern> "$f"`). For `other`: the write succeeds (exit 0) and the admission carries an advisory naming the masking pipe, which the CLI prints on stderr. A here-string is not offered: `lore verify` runs `sh -c` (`service/verify-spawn.ts:43`) and `<<<` is not POSIX. Accepted false positives, biased to refusal as the existing comment at `evidence-precheck.ts:995-1003` already decides: a command after `set -o pipefail`, and the measured safe form `out=$(...); ec=$?; ... | grep` (31 of 907 stored commands; they stay stored and are re-checked only if changed). Rejected: test/e2e only (a `tsc | tail` hides type errors the same way); refusing `other` too (`grep -c x f | wc -l` is a legitimate count — an advisory keeps it visible); a narrower runner-aware detector (a second parser; the user chose reuse).
- **D8 — a captured red must show the failing test, in the stored tail.** For `--capture` with result `fail` or `expected-fail` and oracle `test`/`e2e`, the persisted output tail (`CAPTURE_TAIL_CHARS` = 4000) must parse to a recognised runner summary with failed count >= 1, via a new `parseFailedCaseCount(stdout): number | null` in `attestation-completeness.ts` that reuses `VITEST_TESTS_LINE_PATTERN`; the bun ` N fail` summary line is the only new pattern (measured: bun prints ` 1 pass` / ` 1 fail` / `Ran 2 tests across 1 file.`). The check reads the stored tail, not the full output: the row must carry its own proof for a later reader, so a summary pushed out of the tail (e.g. by later stderr when the command lacks `2>&1`) is refused with a message naming `2>&1`. `fail` is included with `expected-fail` because `lore done`'s red-first floor accepts both. Known limit: the check proves "a runner-shaped summary with a failure appeared in the output", not "a test ran" — a command that prints such a line by hand passes it (AC-EH-9 (b) relies on exactly that); the attestation still records the real exit code and command for review. Rejected: `expected-fail` only (the same broken-command red would clear the floor as `--result fail`); scanning the untruncated output (the stored row could then not show its own proof); a parser in the adapter (second copy of the summary formats).
- **D9 — exit 126/127 is never a red** on the capture path, for any oracle, for captured `fail`/`expected-fail`: refused naming the code ("command not executable" / "command not found"). Rejected: recording such runs as `inconclusive` (the caller asked for a red and gets none; a refusal makes them fix the command).
- **D10 — one precheck function for D8 + D9**, `findCapturedRedProofGap(input)` in `evidence-precheck.ts`, returning a `LoreError | null`, called by the CLI (`commands/evidence.ts`) and MCP (`tools.ts`) at the same point as `findCapturedFailDiscoveryRefusal`, after it, so a discovery refusal keeps its own message. `captureOracleCommand` (`evidence-capture.ts`) stays unchanged: it still reports the observed outcome; the precheck decides.
- **D11 — the falsify path refuses the same non-reds.** `_runFalsifier` checks the mutated run before comparing exit codes: a runner discovery refusal (`findDiscoveryRefusal`) or an exit code of 126/127 records `inconclusive` with `capture_source: "runner-unattested"`, no attestation, outcome code 3 (as BR-189's control path), even when the code equals the declared one (BR-1075).

## Public Interface

```ts
// packages/core/src/task-workflow.ts
export const CAPTURE_SOURCES = ["runner", "self-report", "runner-unattested"] as const;
// packages/core/src/command-pipe.ts (moved, signature unchanged)
export function commandHasUnsafePipe(command: string): boolean;
// packages/core/src/attestation-completeness.ts
export function parseFailedCaseCount(stdout: string): number | null; // null = no recognised summary
// packages/lore/src/adapters/cli/evidence-precheck.ts
export function findCapturedRedProofGap(input: { oracle: string; result: string; capture: boolean; exitCode: number | null; outputTail?: string }): LoreError | null;
// packages/lore/src/service/ac-write-chokepoint.ts — AcWriteAdmission gains advisories: string[] (pipe under oracle other)
```

`lore status --json`: `capture_source_runner_unattested_count`; `lore status --enumerate capture_source_runner_unattested_count`. CLI `lore ac add|set` prints each admission advisory on stderr as `advisory: <text>`.

## Edge cases

| Input | Result |
|---|---|
| `verify --falsify`, control exits 1 | inconclusive, `runner-unattested`, no attestation, outcome 3 |
| row `runner-unattested` + `attestation` (task or phase writer) | VALIDATION_ERROR, nothing written |
| stored `pass` row labelled `runner-unattested`, no attestation | does not satisfy `lore done`'s attested-pass floor |
| `ac add ... --falsifier-exit-code 0` / `-1` / `256` | exit 4, nothing stored |
| `ac add ... --falsifier-exit-code 1` / `255` | exit 0 |
| document create carrying a criterion with falsifier 0 | refused, nothing created |
| `ac set` statement only, stored falsifier 0 | exit 0 (not re-checked) |
| `verify --falsify`, stored falsifier 0 | exit 4, nothing run, no row |
| `ac add` test / e2e / tsc / lint / build, `x \| tail -1` | exit 4 naming the pipe |
| `ac add` other, `grep -c x f \| wc -l` | exit 0, stderr advisory naming the pipe |
| `ac add` test, `grep 'a\|b' f` (quoted) / `a \|\| b` | exit 0, no advisory |
| `ac add` test, `set -o pipefail; vitest run x \| tail` | exit 4 (accepted false positive) |
| `ac set` statement only, stored piped test command | exit 0 |
| capture test expected-fail, exit 1, `Tests  1 failed \| 2 passed (3)` | recorded |
| capture test expected-fail, exit 1, bun ` 1 fail` + `Ran 3 tests across 1 file` | recorded |
| capture test expected-fail, exit 1, `cd: no such file` (no summary) | refused, nothing written |
| capture test fail, exit 1, `Tests  3 passed (3)` (0 failed) | refused |
| capture test expected-fail, summary followed by > 4000 chars of stderr (no `2>&1`) | refused naming `2>&1` (summary not in stored tail) |
| capture any oracle, fail/expected-fail, exit 127 or 126 | refused naming the code |
| capture other, expected-fail, exit 1, no summary | recorded (D8 is test/e2e only) |
| capture test expected-fail, command prints a fake vitest failure line | recorded (known limit, D8) |
| falsify, mutated run prints `No test files found, exiting with code 1`, declared 1 | inconclusive `runner-unattested` |
| falsify, mutated run exits 127, declared 127 | inconclusive `runner-unattested` |
