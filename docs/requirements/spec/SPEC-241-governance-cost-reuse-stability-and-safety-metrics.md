## Overview/Goal

Answer evaluation questions F (governance cost), G (corpus health), H (cost in tokens), I (knowledge reuse), J (spec stability) and K (safety) (OST O5, O6, O7, O8; benchmark gap rows 15, 24, 25 and table-stakes row 12). Today `hook:subagent-stop-commit-guard` denies 512 of 910 runs and nobody can tell how many denials were wrong, because a check outcome records only check id, outcome and time. Token cost is not recorded at all; reuse and stability exist only as raw tables.

Staged requirements R-42 to R-47. Baseline: leaves `baseline-measure-operating-overhead`, `baseline-measure-corpus-fitness`, `baseline-measure-safety` (proposed rules below); BR-1373 modified (check outcomes name actor and subject). Depends on S-A (envelope, origin).

## Scope

| Metric | Question | Definition | Source |
|---|---|---|---|
| `governance.deny_rate` per check | F | Denies over runs per check id | check outcomes (reuses `lore checks stats`), gate and hook-ingested rows, both stores |
| `governance.false_deny_rate` per check | F | Denies followed within 24 hours by a pass of the same check for the same actor on the same subject with the same content fingerprint, over denies | check outcomes with actor, subject, fingerprint |
| `cost.tokens_per_landed_task` | H | Per task that landed in the window: input + output tokens its claims spent, whenever spent, summed over the runs joined by session and helper-agent reference. Unapportioned: tokens with no claim or several claims (in the window spent) and tokens of tasks released unlanded (in the release window). Tokens of not-yet-landed tasks only in the current window, provisional. A closed window never changes. Cache-read apart; no joinable record → no_data with cause (BR-1400, BR-1417) | harness session records (`metrics.sources.session_records`, default the harness's local project transcript directory) |
| `health.*` | G | The `lore eval` scenario results (tree, links, types, placeholders) and staleness counts, read as they are | existing scenarios |
| `reuse.served_doc_use_rate` | I | Distinct documents served by feed or search to a run that the same run's claimed task later links, cites or anchors, over documents served | usage trace + links + anchors |
| `stability.reopen_cycles` | J | Approved → draft transitions per spec per 30 days | version history |
| `safety.reversed_auto_decisions` per class | K | Automatic decisions later reversed over settled ones, from the outcome sweep | decision record (outcome rows) |

## Out of scope

- Hook overhead timing (OST O5-S2): Claude Code OpenTelemetry `hook_execution_*` needs an external collector; reported as no_data naming the missing source until a local source exists.
- Estimating tokens from duration × price (OST O6-S3): rejected unless the phase-1 comparison shows error ≤ 30%.
- Deleting never-read documents (OST O7-S3): a corpus decision, not measurement.

## Design Decisions

| # | Decision | Chosen | Rejected and why |
|---|---|---|---|
| D-D1 | False-deny signal | Same party + same subject + same content fingerprint passes within 24 hours after a deny (BR-1399) | Hand labelling (fails with no human present) |
| D-D2 | Capturing actor and subject | Recorded with every check outcome at write (BR-1373 modified) | Joining check outcomes to the audit trail by timestamp (two concurrent sessions denied in the same millisecond cannot be told apart) |
| D-D3 | Token source | The harness's own local session records, joined to runs by session id (OST O6-S1, 🎲 accepted bet) | OpenTelemetry `token.usage` (external collector); duration × price estimate (unverified error) |
| D-D4 | Question G | Read existing `lore eval` results through the envelope | A second health computation (two numbers for one fact) |
| D-D5 | Reuse attribution | Same run served then used | Any later use by any run (inflates reuse with unrelated reads) |
| D-D7 | Two false-deny figures (S3 crossdoc 7) | Retire BR-488 (usage report's same-actor estimate); BR-1399 is the one figure | Keeping both under different names (two numbers for one question) |
| D-D12 | Which window token cost belongs to (review rev2-4, rev3-4) | A window selects tasks by landing time and counts all their apportioned tokens whenever spent; unapportioned tokens are fixed by spend or release time; not-yet-landed tokens appear only in the current window as provisional, so a closed window never changes | Selecting tokens by spend time (a closed window's per-task figure would change when its tasks land later); dropping not-yet-landed tokens (hides current cost) |
| D-D8 | Token apportioning (S3 eng 7) | Join by session and helper-agent reference; tokens go to the task claimed at the time; no claim or several claims → unapportioned; cache-read apart | Session-level sum per task (double counts two tasks in one session) |
| D-D9 | Reuse attribution (S3 eng 7) | Per requesting run, helper agents apart; serves without a run counted unattributed | Per session (sibling helpers would count each other's use) |
| D-D10 | Scope (S3 PS2) | One metric per P2 question: J reopen cycles, K reversed automatic decisions | AC rewrites and incident counts (dropped from v1; incidents stay an O8-S2 experiment output) |
| D-D11 | Hook outcomes and older rows (S3 eng 6, review rev-4, rev2-4) | Party, subject and fingerprint on gate outcomes and on hook outcomes taken in from the hook log, both SQLite and Turso stores; for the commit guard: the stopping helper's run, its worktree, its head commit plus uncommitted changes (BR-1373). Rows written before capture began form a sealed pre-capture period: the false-deny rate starts at the capture start date, which the output states with the count of earlier denials (BR-1399) | A permanent `unattributable` category inside the rate (a legacy state kept forever); dropping older rows (the deny rate would shrink silently) |

Falsifier literals implementers must keep: `FALSE_DENY_WINDOW_HOURS = 24` in `packages/lore/src/service/metrics/overhead-metrics.ts`; `subject_fingerprint` in `packages/lore/src/service/gate-enforcer.ts`; `"usage"` in `packages/lore/src/service/metrics/session-records.ts`; `sameRun(` in `packages/lore/src/service/metrics/corpus-fitness-metrics.ts`; `"approved"` in `packages/lore/src/service/metrics/corpus-fitness-metrics.ts`; `"reversed"` in `packages/lore/src/service/metrics/safety-metrics.ts`.
