## Overview/Goal

A judging-instruction (prompt) version must not become current without passing a calibration gate (user decision D20, S3 round 2 design 6). Today a version becomes current when a developer changes `REVIEW_PROMPT_VERSION` in `packages/lore/src/ai/review-template.ts`; nothing measures it first. Plan 1's experiment O2-S3 showed the cost (`knowledge-experiment-o2-ai-decision-labels-auc-and-audit-cost`): the spec judge at version v2 was current from 2026-07-26 to 2026-10-10 with AUC 0.406 and DeLong 95% lower bound 0.333 over 282 labelled judgments (bar 0.65; with set-back events removed AUC 0.582, bound 0.486), and its confidence did not separate right from wrong verdicts (0.768 vs 0.783). Versions v3 to v8 replaced each other faster than 30-day outcome labels accrue, so none has been measured, and #414 is about to add v9.

This spec replaces "current = a code constant" with "current = the latest version that passed promotion": a candidate version judges the labelled document versions again and is promoted only when its AUC lower bound reaches 0.65 on every measurable document type (BR-1461); the judge uses only the promoted version and refuses when none passed (BR-1462); judgments under every older version stay labelled by version, retired ones marked retired (BR-1426), which is how v2's history is kept.

## Scope

- `lore calibration promote <version> [--kind review]` (BR-1461): replays the candidate over the labelled document versions (outcome labels from S-B's labelling, BR-1387 and BR-1411, which do not depend on which judge version judged them; AI-judge rows only, BR-1422), per document type with at least 10 labelled versions per class computes AUC and the DeLong 95% lower bound, stores the attempt (per-type results, measured or insufficient) with an audit entry, and appends a promotion row only when at least one type is measured and every measured type reaches 0.65. With no measured type the attempt is stored as `not_measurable`, never a pass; a fail or `not_measurable` exits 4 and the current version stays. Append-only; no update or delete.
- Holdout and attempts (BR-1469): only the holdout decides: a labelled document version is in it when the SHA-256 of its version id, read as an integer, mod 100 is below 30 (deterministic, the same in every process, no stored assignment, so concurrency-safe); the other 70% is the tuning split a prompt author may look at, and it never decides. Every attempt is stored and printed with its attempt number for that version and the number of attempts since the last promotion, so repeated retries against the holdout are visible in the output and the store.
- The AI judge (BR-1462) reads its version from the latest passing promotion (`ai-provider-service.ts` template selection); `REVIEW_PROMPT_VERSION` no longer chooses it. No passing promotion: judging refuses with exit 4 and writes nothing.
- Calibration statistics (BR-1426, BR-555): each group carries `prompt_status` and `last_judged_at`, split by origin: `current` = the version of the latest passing promotion of its kind; `retired` = any other version of a kind that has a passing promotion; `unpromoted` = every version of a kind with no passing promotion (staleness and milestone review today). This is the end-state meaning, not a transitional state: a version without a promotion is never current. Nothing is excluded or relabelled; a retired version stays readable with `--prompt-version`.
- The v2 finding above is kept as this spec's record; v2 never passed promotion, so it shows retired.

## Out of scope

- The labelling rule itself. The set-back after-event counts an edit-demotion of an approved spec as a reversal (587 of 637 linked events); that confound belongs to S-B (BR-1387). It is enforced, not only stated: S-B's labels task (task-outcome-labels-brier-reliability-bins-and-judge-auc) carries a must-resolve item to fix it through an S-B revision, and blocks this plan's gate task and its switch task, whose precondition step makes the first real promotion.
- A promotion mechanism for staleness and milestone-review prompt versions: until one is specified, their versions are `unpromoted` (above), which is the permanent meaning of having no promotion; this spec does not add one.
- #414's v9: it becomes current only by passing this gate once both land (coordination with the governance plan, which owns the cross-initiative link).

## Design Decisions

| # | Decision | Chosen | Rejected and why |
|---|---|---|---|
| RJ-D1 | What this spec is about (D20) | The mechanism: no version becomes current without a calibration gate; v2's history is one case of it | Only labelling v2's history (round 1: an instance; the next unmeasured version, v9, would repeat it); merging into S-B (D20 keeps a separate spec; S-B scores judges, this decides which judge is used) |
| RJ-D2 | Gate measure | DeLong 95% lower bound of AUC ≥ 0.65 on every document type with ≥ 10 labelled versions per class, and at least one type measured; an attempt with no measured type is stored `not_measurable` and is never a pass | AUC point value (n is small, interval about ±0.2; O2-S3 pre-registered the lower bound); "every measurable type passes" without the at-least-one clause (vacuously true when nothing is measurable, so an untested version would be promoted); waiting 30 days for live labels of the new version; Brier alone |
| RJ-D3 | Labels for a candidate that has never judged live | Replay: the candidate judges the already-labelled document versions of the holdout; labels belong to the document version's outcome, not to the judge | Shadow judging live documents for 30 days (two judges per review, doubles cost, delays every prompt fix) |
| RJ-D4 | Version current when this lands (v8) | Promoted through the same gate as the switch task's precondition step, before the judge reads promotions. If that attempt fails or is `not_measurable` (too few labelled versions), the pre-registered stop fires: the switch task is not claimed, the plan stops and this spec is re-reviewed. Reviews are not blocked meanwhile: until the switch lands the judge keeps choosing its version as today, and the switch never lands without a passing promotion | Seeding a promotion row for v8 without measurement (a grandfathered legacy bucket); landing the switch first and refusing all reviews until some version passes (stops unattended review); keeping the constant as a fallback after the switch when no promotion exists (a silent fallback) |
| RJ-D5 | Historical judgments of retired versions, v2 included | Kept under their own version, labelled retired with last judgment time, split by origin | Excluding them (384 judgments would vanish without a count); relabelling to the current version (pools judges, BR-555); deleting them |
| RJ-D6 | What current, retired and unpromoted mean | Current = latest passing promotion of the kind; retired = any other version of a kind with a promotion; unpromoted = every version of a kind with none; end state, one rule for every kind | A code constant (unmeasured versions become current, the defect); calling staleness versions current without a promotion (a second, unspecified path to current); limiting prompt_status to the review kind (other kinds' groups would carry no status) |
| RJ-D7 | Where the rules live | Review branch, leaf `baseline-judge-a-document` (the pre-registered path names the review branch) | `baseline-read-calibration-statistics` only (the version life cycle belongs to the judge) |
| RJ-D8 | Over-fitting the gate set (S3 review rv5) | Fixed hash holdout (30%) decides; tuning split (70%) never decides; every attempt stored and numbered, attempts since last promotion printed | One fixed set used for both tuning and decision (a prompt can be revised until it clears 0.65); a random split per attempt (not reproducible, and two processes would judge different sets); a fresh holdout only from new labels (too few labels accrue per month); a hard cap on attempts (a fixed number nobody can justify; visibility lets the reviewer judge) |
| RJ-D9 | Label confound before the first promotion (rv5) | Task-level blocks link from S-B's labels task, which must resolve the confound through an S-B revision, to this plan's gate and switch tasks | A sentence in Out of scope only (round 4: not enforced); a label-rule version stamped on each attempt with promotion refused until it changes (needs a label versioning mechanism S-B does not have) |

Falsifier literals implementers must keep: `"retired"` in `packages/lore/src/service/judgment-service.ts`; `AUC_LOWER_BOUND_MIN = 0.65` in `packages/lore/src/service/judge-promotion.ts`; `% 100n < 30n` in `packages/lore/src/service/judge-promotion.ts` (AC-RJ-4); `REVIEW_TEMPLATES[promoted.version]` in `packages/lore/src/service/ai-provider-service.ts`.
