## Worktree-derived actor identity (landed 2026-07-28, SPEC-104)

Actor provenance had a silent failure mode that no amount of prose could close: the anchor-overlap gate (SPEC-042) is only as strong as per-dispatch `LORE_ACTOR` discipline, and when every agent falls back to the same OS username the gate can never fire — a whole class of concurrent-collision protection going dark while every command still exits 0. The only signal was one stderr advisory. Cross-corpus evidence made the cost concrete: one project ran 50+ agent worktrees with ZERO lore claims, and the corpus that DID hold discipline held it only through per-dispatch vigilance.

Resolution now has a deterministic tier between the named sources and the OS fallback: **explicit `--by` > `$LORE_ACTOR` > session tier > worktree-derived `agent:<branch>` > OS username**. Detection is filesystem-only — no `git` subprocess — walking cwd upward for a `.git` FILE (a linked worktree's `gitdir:` pointer; the main checkout has a `.git` DIRECTORY) and reading HEAD through that pointer. Branch names map verbatim, so identity matches the existing `agent:<branch-or-slug>` convention and git's own refusal to check one branch out twice supplies collision-freedom for free. Any anomaly — detached HEAD, unreadable gitdir — fails OPEN to the legacy OS-username path with its warning; actor resolution must never crash a command.

The accepted limitation is documented rather than hidden: a HUMAN working in a linked worktree without an explicit identity is attributed `agent:<branch>`. Every explicit path is unchanged, the resolution tier is visible in the claim guard's `identitySource`, and the human-in-a-linked-worktree-without-identity case is rarer than the failure mode this replaces — which was measured, not assumed.

Deliberately NOT built: refusing OS-fallback claims outright. A forced invented identity is less traceable than a derived one, so friction there would have bought nothing.
