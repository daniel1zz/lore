## FEED — pull governance before you produce

- Session bootstrap is hook-injected where configured — EVERY field (`my_claims` / `active_sessions` / `armed_gates` / `root` / `pending_reviews` / `active_plans` / `latest_handoffs` / `corpus` / `archive_candidates`, plus any seat-scoped conditional field) is corpus-global — spanning every plan, every actor, every concurrent session — never this session's worklist, never any handoff ticket's scope. Consume it directly, do not re-fetch it yourself. `latest_handoffs` is a NEUTRAL directory of open threads across every plan, not a pointer to "the" thread — the user is the router. NEVER start resuming work from an injected handoff pointer on your own initiative; resume ONLY on the user's pasted ticket (`lore feed session-resume --handoff <slug>`) or an explicit instruction.
- When reporting state to the user, label each item by source — pasted ticket / session-start injection / this-turn query — never merge them into one undifferentiated list: obeying the resumption rule alone does not satisfy this duty (measured 2026-07-30: a report merged sources though the assistant never self-resumed).
- Resuming interrupted work: `lore feed session-resume [--by <actor>] [--plan <plan>]`.
- A consumed resume ticket is bounded from BELOW as well as from above: it prints one ordinal-tagged line per item (`KD<n>` per key decision, `NS<n>` per next step), preceded by a cardinality line stating how many items there are in total. Account for EVERY printed item before the session ends — one line each, `**[RESUME_DISPOSITION]** <item-id>: done` or `**[RESUME_DISPOSITION]** <item-id>: deferred:<reason>`. The obligation is to ACCOUNT, not to complete: a ticket whose items are all legitimately out of this session's scope closes cleanly once every item carries its own deferral reason AND that reason names WHERE the deferred work went — a filed issue reference (`#<n>`) or a corpus slug. A reason alone is not a destination: it is refused behind its own stderr prefix, distinct from the bare-`deferred:` one, because "no reason given" and "a reason that parks the work nowhere" are different mistakes with different fixes. New problems found mid-session belong in `lore report-issue`, not in this session's scope — that is what makes the deferral honest and lets the original task close (measured 2026-08-25: of 696 next-step items across 139 handoffs, 458 were bare prose that entered no queue). None may go unmentioned — the Stop-time coverage check names the undispositioned ids and blocks the turn. Obeying the scope declaration alone does not satisfy this duty; the two bound opposite directions (measured 2026-07-30: a report dropped 3 of 10 printed items while trespassing on nothing).
- Verifying a handoff you JUST AUTHORED costs you nothing: the floor arms only for a ticket authored by a different actor or in an earlier session, so rendering your own outgoing ticket to confirm it is consumable does NOT charge you with the next-steps you are handing off. Verify it — the discipline of never trusting an unseen artifact applies to the resume command you hand the user. When the check cannot determine authorship (no session marker), the floor arms; that is deliberate fail-safe, so account for the items normally in that case.
- Before producing any artifact: `lore feed <checkpoint>` (e.g. `spec-create`) pulls the governing rules slice plus upstream summaries — pull proactively, do not wait for a gate to reject you first.
- Search first: `lore search "<topic>" --json` / `lore get <slug>` / `lore tree [<plan>]` — link to an existing doc with `lore link` instead of duplicating it.
