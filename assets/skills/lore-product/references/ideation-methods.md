# Ideation Methods Reference

> Method selection guide and application triggers — not full methodology.

## Pre-Ideation Check (MANDATORY)
- Are we solving the right problem? Is it worth solving? Have others tried?
- Red flags: "We already know what to build" (confirmation bias), "Solution is obvious" (underexplored), "Everyone agrees" (groupthink), "No one has done this" (usually wrong)

## Method Selection

| Situation | Method | Key |
|-----------|--------|-----|
| Need volume | Brainstorming / Brainwriting 6-3-5 | 50-100 raw → cluster → top 3-5 |
| Improving existing | SCAMPER | Substitute/Combine/Adapt/Modify/Put-to-other-uses/Eliminate/Reverse |
| Bridging problem→solution | How Might We | "HMW {outcome} for {user} when {context}?" Calibrate: not too broad, not too narrow |
| Quick diverse concepts | Crazy Eights | 8 ideas in 8 minutes, sketch-based |
| Understanding needs | JTBD | "When {situation}, I want {motivation}, so I can {outcome}" |
| Root cause analysis | Five Whys | Surface problem → dig to root |
| Understanding emotions | Empathy Mapping | Says/Thinks/Does/Feels → Pains & Gains |

## Prioritization Selection

| Method | When | Key |
|--------|------|-----|
| RICE | Data-driven ranking | (Reach × Impact × Confidence) / Effort |
| MoSCoW | Scope negotiation | Must 60% / Should 20% / Could 20% / Won't |
| Kano | Feature satisfaction analysis | Basic (expected) / Performance (more=better) / Delighters |
| Impact vs Effort | Fast team alignment | Quadrants: Quick wins, Big bets, Fill-ins, Money pits |

## Challenge Techniques
- **Pre-mortem**: "Imagine this failed spectacularly. Why?"
- **Red team**: Strongest case against the idea
- **Outside view**: Base rate of success for this type of product?
- **Inversion**: What would guarantee failure? Are we doing any of that?
- **10x test**: What if competitor had 10x our resources?
- **Customer switch test**: 10x better to justify switching cost? Slightly better ≠ worth switching.

## Idea Evaluation (in order, fail-fast)
1. Problem quality — hair-on-fire or nice-to-have? **Weak = kill**
2. Market attractiveness — growing/shrinking? fragmented/dominated?
3. Competitive advantage — why will we win? copyable?
4. Execution fit — skills and resources?
5. Passion alignment — still want this in 3 years?

## Quick Validation Methods

| Method | What | Success Signal |
|--------|------|---------------|
| Assumption mapping | Plot on Importance × Evidence | Test high-importance low-evidence first |
| Fake door test | Show feature, measure interest pre-build | >5% CTR, >20% leave email |
| Wizard of Oz | Manual behind automated facade | Learn requirements before building |
