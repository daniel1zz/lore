# Module: core

## Purpose

Foundational types, error model, runtime validation, lifecycle rules, config, and telemetry. Pure modules with no I/O except `config.ts` (file read/write) and `telemetry.ts` (append-only JSONL). Published as `@lore/core` workspace package; depends on no other `@lore/*` package. Browser-safe distribution leaves: `memory-markers.ts` (CLAUDE.md managed-section markers + fingerprint grammar) and `fs-ports.ts` (`FsReadPort`/`FsWritePort` interfaces + `InMemoryFsPort` test double).

## Key Invariants

- **Browser safety (`index.ts` barrel MUST stay import-safe from a browser bundle)** — `@lore/dashboard` imports only `@lore/core` (never `@lore/core/node`). Vite's dev-mode `fs` stub throws on named-export access **at module-load time**, not call time — a single top-level `import { x } from "fs"` anywhere in the barrel's transitive closure blanks the SPA before React mounts. Node-builtin-dependent code (`fs`/`path`/`os`/`child_process`) is split into `config-node.ts` (loadConfig/saveConfig/resolveGlobalConfigPath/loadGlobalConfig), `telemetry-node.ts` (JsonlTelemetry/createTelemetry), and `slugify-node.ts` (`transliterateCjk`, SPEC-068 — its `pinyin-pro` dep is ~931KB unpacked), all re-exported only via the `@lore/core/node` subpath (`node.ts`, `package.json#exports["./node"]`). `config.ts`/`telemetry.ts` keep pure Zod schemas/types/`NoOpTelemetry` and MUST NOT re-import fs/path/os. Static import-graph oracle: `packages/lore/tests/unit/core/barrel-isolation.test.ts`. Regression oracle: `packages/dashboard/tests/e2e/write-flow.pw.ts` (a `pageerror` before scenario 1 = this bug recurring). Grep check: `grep -rn 'from "fs"\|from "path"\|from "os"\|from "pinyin-pro"' packages/core/src/index.ts packages/core/src/config.ts packages/core/src/telemetry.ts` → 0 hits.
- **`DOC_TYPE_ROLE_MAP`** in `types.ts` is the SSOT for `DocType → DocRole`. Never derive role another way.
- **`ORACLE_KINDS` (`task-workflow.ts`) is the single oracle-enum definition site** — `evidenceEntrySchema.oracle`, CLI `--oracle` choices, and MCP `EVIDENCE_ORACLE_ENUM` all reference it; never redeclare the literal list. `acceptance.ts::SCRIPT_ORACLES` (all kinds except `manual`) is pinned by a type-level exhaustiveness assertion — a new `OracleKind` fails compilation there until classified. Detail: SPEC-038.
- **Evidence `attestation` is OPTIONAL and load-bearing** — `extractEvidence` is whole-array fail-closed (required would silently zero ALL legacy evidence across `ready()`/`computeAcCoverage`/assess). `ATTESTATION_RUNNERS` mirrors `ORACLE_KINDS`, never bare literals. Runner-issued only — public write paths reject it (`TaskWorkflowService.addEvidence` fail-loud); sole injection site `recordVerifiedEvidence`. `resolveTargetTask` = pure heuristic (explicit override > unique fresh claim > loud ambiguity error). `isApprovedVerifyCommand(task, command)` gates command-provenance approval; `LoreError.NEEDS_APPROVAL {message, command, ac_id}` (CLI exit 7) is the refusal path — every exhaustive `switch (error.code)` over `LoreError` needs this case. Detail: SPEC-039.
- **`acceptance.ts` is the AC-as-code SSOT** — `acceptanceCriterionSchema` (id regex `^AC-[A-Z0-9]+(-[A-Z0-9]+)*$`, `verify` discriminated union script/ai/human), `specAcceptanceCriteriaSchema` (max 50, unique ids via superRefine), `computeAcCoverage(criteria, tasks)` — pure, single-pass, facts-only aggregator over task evidence `ac_ref`s; rendering belongs to each consumer, never here. `evidenceEntrySchema.ac_ref` is optional/format-unconstrained here — cross-entity membership validation lives in `TaskWorkflowService.addEvidence` via an injected `resolveDeclaredAcIds` port. `isAcInDeclaredScope(declaredScope, acId)` is the pure membership predicate (exact string equality) `VerifyRunnerService`'s declared-scope selection consumes — it answers `false` for every id when the scope is `[]`, so the CALLER must have already separated an absent scope from an empty one. `deriveAcCoverageState(fact)` is the ONE fail-first precedence derivation, now SEVEN states (`"fail" > "fail_superseded" > "attested_pass" > "not_measured" > "pass_unfalsified" > "pass" > "none"` — full row-by-row rationale, incl. the M4 supersession tie-breaks and M5's well-formedness check, lives ONLY on the governing spec's Design section, never restated here: spec-oracle-tier-falsifiability-a-criterion-never-observed-red M1/M4/M5) — both `task-feed-wiring.ts` and `commands/ac.ts::coverageBadge` consume it. Detail: SPEC-038, SPEC-070.
- **Result over throws** — `errors.ts` defines the `Result<T, LoreError>` discriminated union and `ok()` / `err()` constructors. Modules that import `LoreError` use these helpers, not raw object literals.
- **Slug shape** — `^[a-z][a-z0-9-]{1,62}[a-z0-9]$` (3–64 chars, no leading/trailing hyphen). Generation in `schemas.ts::slugify`; collision resolution (-2, -3, …) delegated to the caller via `slugifyWithCollision`'s `existsSlug` callback (sync or async). CJK support: `slugify(type, title, opts?)` takes an optional `opts.transliterate?: (raw) => string` hook applied before kebab-casing — the real impl (`transliterateCjk`) lives only in `slugify-node.ts`/`@lore/core/node`. An empty-after-kebab non-empty title never falls back to the bare type name — it gets `{type}-{fnv1a32Hex(title)}` (`slug-hash.ts`, pure). A kebab result equal to/prefixed by the type word has that segment stripped before re-prefixing. Truncation at 64 chars cuts to the last complete hyphen token. `CorpusService.set` accepts a `slug` patch — uniqueness-checked, version-logged, deliberately NOT part of the approved→draft auto-reset (slug is an address, not content). Detail: SPEC-068.
- **Session INSTANCE vs actor IDENTITY** — `session-actor.ts::sessionIdDiscriminator(id)` is the SSOT sanitize+slice transform for BOTH spellings of a session: `sessionActorFromId` (the `agent:session-` actor) and `taskClaimSchema.session_id` (the captured claim fact). `deriveSessions` keys on `(by, machine, worktree, session_id)` and `buildTaskClaim` NEVER carries `session_id` forward on a refresh — inheriting it would fabricate same-session evidence. An ABSENT `session_id` means NOT MEASURED, never "same session" (`gate-predicates.ts::compareClaimSessions` is the only comparison). Rationale: two concurrently-live sessions legitimately share one actor string (`task-two-concurrent-orchestrators-both-resolve-to-agent-main`).
- **SPEC-071 liveness pure fns** — `session-actor.ts::sessionActorFromId` (→ `agent:session-<8-char sanitized prefix>`, THROWS on sanitize-to-empty via the shared discriminator, never a bare prefix); `task-workflow.ts::renewClaimForEvidence(claim, actor, nowIso)` (same-holder match fresh OR stale → new claim with updated `at`, foreign/absent → `null`, never mutates input — sole renewal predicate shared by Task/Phase evidence paths); `session.ts::deriveLastActivityAt(plan, tasks)` (max `updated_at` over plan+tasks) + `bootstrapActivePlanSchema.last_activity_at` REQUIRED (fail-loud at `bootstrapReportSchema.parse`).
- **Lifecycle graph** — `VALID_TRANSITIONS` in `schemas.ts` is the only authority on status moves. Three public reads, no more: `isValidTransition(from, to)`, `getAllowedTransitions(from)`, and `resolveStatusAfterContractEdit(currentStatus, contentChanged)` — the sole implementation of the approved→draft contract-edit demotion, shared by `CorpusService.set` and `AcService.setCriterion`. It returns the whole rule (trigger AND target status) so neither caller writes the `"draft"` literal itself; a boolean predicate would have left half the rule mirrored. Do NOT re-inline this demotion in a service: it previously existed twice (`corpus-service.ts` inline + `ac-service.ts::computeSetStatus`) and the two copies were behaviourally identical, so every per-path test passed while the SSOT violation stood — pinned now by `tests/unit/service/demotion-rule-ssot.test.ts`, which stubs the shared fn and asserts BOTH paths follow it.
- **Config: env-var NAME, never plaintext (D-004)** — `sync.auth_token_env` stores the variable name (`"LORE_SYNC_TOKEN"` by default). `resolveSyncCredentials()` reads `process.env` at call time and fails loud (`VALIDATION_ERROR`) when missing or empty.
- **Memory-file budgets: ONE seam, provenance-carrying** — `resolveMemoryFileBudgetsFromConfigResult` returns a discriminated `MemoryFileBudgetResolution`, never a bare `MemoryFileBudgets`; `formatMemoryFileBudgetSubstitution` is the sole renderer for both CLI consumers. ⛔ Three of five sources legitimately end at schema defaults and MUST stay silent — only `substituted-defaults` speaks, so a boolean "used defaults" is not a valid simplification. ⛔ Never re-inline in a consumer, never loosen `contextConfigSchema` to dodge a refusal. `task-lore-status-check-claude-md-silently-runs-on-schema`
- **Telemetry never throws** — `JsonlTelemetry.record()` swallows IO errors; `close()` is idempotent; post-close `record()` is a no-op. Caller-visible behaviour is identical between `NoOpTelemetry` and `JsonlTelemetry`.
- **`frontmatter.ts::splitFrontmatter(text, mode)`** — shared `---`-delimiter split (no `yaml` dependency; callers parse the returned string themselves). REQUIRED `mode`, no default: `"loose"` (migration's v1-markdown dialect — closing marker bare `"\n---"`, both sides trimmed) vs `"strict"` (export-docs' v2-corpus dialect — exact `"---\n"`/`"\n---\n"`, neither side trimmed). Pre-processing (BOM/CRLF) stays each caller's own job.

## Patterns

- **Zod is SSOT for runtime-validated shapes** — `TelemetryEventSchema`, `LoreConfigSchema`, `createDocInputSchema`, etc. Derived TS types come from `z.infer<typeof Schema>`; never duplicate the shape as a hand-written interface.
- **Type-specific validation via `superRefine`** — `createDocInputSchema` enforces `spec/task → parent_id`, `adr → extra.decision_status`, `knowledge → extra.sub_type`, `task → extra.plan_id`, `plan → extra.phases uniqueness` (`schemas.ts`).

### AI Plan-Outcome Assessment Schema

`assessment.ts` is pure/browser-safe (no IO, no wall-clock reads). `llmAssessmentOutputSchema` = raw judge-output shape (excludes `scope`/`judgment`, layered on by `AIProviderService.assessPlan`); `assessmentResultSchema` = persisted shape, validated by `knowledgeExtraSchema.extra.assessment` whenever `sub_type === "assessment"` (only `lore assess`/`lore_assess` write this sub_type). `planBundleSchema`/`PlanBundle` assembled by `CorpusService.getPlanBundle`. `extractAssessmentJson` = tolerant JSON extraction (bare → fenced → prose-wrapped), never throws, does not validate shape. `truncateSection`/`renderAssessmentContent` (deterministic Markdown, SSOT is `extra.assessment`). `AiConfigSchema.assess` holds the four char budgets. SPEC-040 adds service-computed `facts`/`source_versions` (judge never writes), `dimension_scores`/`typed_gaps`/`typed_recommendations`/`unverifiable`/`rubric_warning`; `computeAssessmentFacts` is the pure facts aggregator consumed (never recomputed) by `buildAssessPromptV6` (`ai/assess-template.ts`). Detail: SPEC-026, SPEC-040.

### Plan Phases Schema Invariants

`planExtraSchema` (`schemas.ts`): `phases[]` max 30, unique `name` (superRefine, case-sensitive exact-match, caller trims). `phase?` is legacy/deprecated — `lore migrate phases` converts it to `legacy_phase`; **do not read `extra.phase` on plans**, use `extra.phases[]`. `taskExtraSchema.phase` is validated against the parent plan's `phases[].name` by `CorpusService` (cross-entity, not Zod); absent is always valid. `ac_scope?: string[]` (`acScopeArraySchema`: non-empty AC-id STRINGS, but the ARRAY itself may be EMPTY — `[]` is an explicit "no criterion claimed" declaration and is load-bearingly distinct from absence, which `extractDeclaredAcScope` preserves; the non-empty constraint belongs to the PLAN tier's own `planAcScopeSchema`) — membership checked by `CorpusService`, consumed by `computeAssessmentFacts`/`buildAssessPromptV6` for scope/dangling marking, and its PRESENCE (empty included) arms `lore done`'s no-new-tests floor (task-the-ac-scope-re-keying-left-the-red-first-floor-unarmed). Detail: SPEC-023, SPEC-040.
- **Parent-type contract** — `doc-type-rules.ts::PARENT_TYPE_CONTRACT` and `isValidParentType(child, parent)` are imported by `CorpusService` and `TreeCheckService`. Adding a new doc type requires updating this contract.
- **Graph helpers stay pure** — `graph-utils.ts::ancestorChainWalk` and `tree-blueprint.ts` operate on plain data; they don't take a `StoreInterface`. Callers fetch the data and pass it in.
- **`file-anchors.ts` resolution half is pure and ADVISORY** — `classifyFileAnchorResolution(anchors, probes)`/`fileAnchorProbePath`/`unprobedFileAnchors` take ALREADY-COLLECTED filesystem observations (same shape `computeDrift` takes), because this package is browser-safe: the fs port + the one advisory renderer live in `packages/lore/src/service/anchor-resolution.ts`, reusing `DriftCheckService`'s `FsProbe`. ⛔ `normalizeFileAnchors` must NEVER gain an existence check and a non-resolving anchor is never a refusal at any layer — a task's `file_anchors` are declared BEFORE the work (anchoring a to-be-created file is legitimate and is exactly the highest-risk mutex case), unlike a spec's `code_anchors`, declared after landing, which `--check-drift` DOES report as `file_missing`. `FileAnchorResolutionReport` is a discriminated union so `{probed:false}` can never read as `{probed:true, unresolved:[]}` — not-probed ≠ nothing-found. ⛔ Anchors stay opt-in, so this only makes the DECLARED set trustworthy; it closes no mutex hole. SSOT: `task-a-mistyped-task-file-anchor-is-stored-and-consulted`.
- **Config side effects isolated to `loadConfig`/`saveConfig`** (`config-node.ts`, `@lore/core/node` subpath) — `parseConfig`/`loadConfigFromString` (`config.ts`, default barrel) are pure and Result-returning; tests pass YAML strings, not file paths.
- **`doc-type-meta.ts::deriveTypeMeta(doc, opts?)`** is the single derivation point for `DocSummary.meta` (browser-safe, no Node imports) — a discriminated union keyed by `doc.type`. Never throws on malformed/legacy `extra`; degrades by omission (one documented default: absent `spec_kind` → `"feature"`). Reads `Date.now()` ONLY for `task.claim_stale` when `opts.claimTtlMinutes` is supplied (narrow deviation from this package's no-wall-clock convention). Reuses `task-workflow.ts`'s `extractEvidence`/`extractClaim`. Detail: SPEC-036.
