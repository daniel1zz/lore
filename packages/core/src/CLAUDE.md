# Module: core

## Purpose

Foundational types, error model, runtime validation, lifecycle rules, config, and telemetry. Pure modules with no I/O except `config.ts` (file read/write) and `telemetry.ts` (append-only JSONL). Published as `@lore/core` workspace package; depends on no other `@lore/*` package.

## Key Invariants

- **Browser safety (`index.ts` barrel MUST stay import-safe from a browser bundle)** — `@lore/dashboard` imports only `@lore/core` (never `@lore/core/node`). Vite's dev-mode `fs` stub throws on named-export access **at module-load time**, not call time — so a single top-level `import { x } from "fs"` anywhere in the barrel's transitive closure blanks the SPA before React mounts, even if the importing code path never runs in-browser. Node-builtin-dependent code (`fs`/`path`/`os`/`child_process`) is split into `config-node.ts` (loadConfig/saveConfig/resolveGlobalConfigPath/loadGlobalConfig) and `telemetry-node.ts` (JsonlTelemetry/createTelemetry), both re-exported only via the `@lore/core/node` subpath (`node.ts`, `package.json#exports["./node"]`). `config.ts` and `telemetry.ts` keep the pure Zod schemas/types/interfaces/`NoOpTelemetry` and MUST NOT re-import fs/path/os. `slugify-node.ts` (`transliterateCjk`, SPEC-068 D1) joins this split for the SAME reason despite performing no filesystem IO itself — its `pinyin-pro` dependency is ~931KB unpacked and must stay unreachable from the bundle; see `packages/lore/tests/unit/core/barrel-isolation.test.ts` for the dedicated static import-graph oracle. **Regression oracle**: `packages/dashboard/tests/e2e/write-flow.pw.ts` (SPEC-022, Playwright) — a `pageerror` in that suite before scenario 1 completes is this exact class of bug recurring. Grep check: `grep -rn 'from "fs"\|from "path"\|from "os"\|from "pinyin-pro"' packages/core/src/index.ts packages/core/src/config.ts packages/core/src/telemetry.ts` → 0 hits.
- **`DOC_TYPE_ROLE_MAP`** in `types.ts` is the SSOT for `DocType → DocRole`. Never derive role another way.
- **`ORACLE_KINDS` (`task-workflow.ts`) is the single oracle-enum definition site (SPEC-038 D3)** — `evidenceEntrySchema.oracle`, CLI `--oracle` choices, and MCP `EVIDENCE_ORACLE_ENUM` all reference it; never redeclare the literal list. `acceptance.ts::SCRIPT_ORACLES` is a deliberate explicit-literal subset (all kinds except `manual`) pinned by a type-level exhaustiveness assertion — adding a new `OracleKind` fails compilation there until someone decides whether it is script-verifiable.
- **`attestation` on evidence entries is OPTIONAL and load-bearing (SPEC-039 D1)** — `extractEvidence` is whole-array fail-closed: making `attestation` required would silently zero ALL legacy evidence across `ready()`/`computeAcCoverage`/assess. `ATTESTATION_RUNNERS` is the runner-id tuple (mirror of `ORACLE_KINDS`, never bare literals). Attestation is runner-issued only — public write paths reject it (`TaskWorkflowService.addEvidence` fail-loud); the sole injection site is `recordVerifiedEvidence`. `resolveTargetTask` (task-workflow.ts) is the pure target-task heuristic (explicit override > unique fresh claim > loud ambiguity error), composing `extractClaim`/`isClaimStale`. **SPEC-039 §M2 trust-hardening (2026-07-13)**: `attestation` gains an OPTIONAL `first_seen?: boolean` field (present-iff-true, additive/REGRESSION-safe — a legacy attestation object with no `first_seen` still parses) — set by `VerifyRunnerService` when the executed command was new/changed relative to the task's evidence history. `isApprovedVerifyCommand(task, command)` (task-workflow.ts) is the pure exact-string-match predicate behind both the command-provenance approval gate and this annotation. `LoreError` gains `NEEDS_APPROVAL {message, command, ac_id}` (`errors.ts`, CLI exit 7) — returned when `lore verify`/`lore_verify` refuses to execute an unapproved command; every exhaustive `switch (error.code)` over `LoreError` in the codebase (`adapters/cli/utils.ts`, `adapters/http/middleware.ts`, `eval/scenarios/placeholder-parse.ts`) has a case for it.
- **`acceptance.ts` is the AC-as-code SSOT (SPEC-038)** — `acceptanceCriterionSchema` (id regex `^AC-[A-Z0-9]+(-[A-Z0-9]+)*$`, `verify` discriminated union script/ai/human), `specAcceptanceCriteriaSchema` (max 50, unique ids via superRefine), and `computeAcCoverage(criteria, tasks)` — a pure facts-only aggregator over task evidence `ac_ref`s (`{ac_id, mode, pass, fail, refs}`); rendering belongs to each consumer (CLI badge, outline projection, assess prompt), never here. Browser-safe, no wall-clock reads. `evidenceEntrySchema.ac_ref` is optional and format-unconstrained at this layer — cross-entity validation (declared-id membership) lives in `TaskWorkflowService.addEvidence` via an injected `resolveDeclaredAcIds` port implemented by `CorpusService`.
- **Result over throws** — `errors.ts` defines the `Result<T, LoreError>` discriminated union and `ok()` / `err()` constructors. Modules that import `LoreError` use these helpers, not raw object literals.
- **Slug shape** — `^[a-z][a-z0-9-]{1,62}[a-z0-9]$` (3–64 chars, no leading/trailing hyphen). Generation lives in `schemas.ts::slugify`; collision resolution (-2, -3, …) is delegated to the caller via `slugifyWithCollision`'s `existsSlug` callback (sync or async). **SPEC-068 CJK-aware slugify + repair path**: `slugify(type, title, opts?)` gains an optional `opts.transliterate?: (raw) => string` hook applied to the raw title BEFORE the kebab step (D1) — the real pinyin-pro-powered implementation (`transliterateCjk`) lives in `slugify-node.ts`, exported ONLY via `@lore/core/node` (never the default barrel; `pinyin-pro` is ~931KB unpacked and must stay unreachable from the browser bundle — same split as `config-node.ts`/`telemetry-node.ts`, verified by a static import-graph test). A non-empty title that transliterates+kebabs to an empty name part never falls back to the bare type name (D2) — it gets `{type}-{fnv1a32Hex(title)}` instead (`slug-hash.ts`, pure, browser-safe). A kebab result equal to or prefixed by the type word has that leading segment stripped before re-prefixing (D3, prevents `adr-adr-…`). Truncation at 64 chars cuts back to the last complete hyphen token unless the first token alone overflows (D4). `slugifyWithCollision` forwards `opts` unchanged. `CorpusService.set` additionally accepts a `slug` patch (D5) — uniqueness-checked (VALIDATION_ERROR naming the holding doc), a no-op when restating the doc's own current slug, version-logged like any other `set` call, and deliberately NOT part of the approved→draft auto-reset trigger (slug is an address, not content).
- **SPEC-071 liveness pure fns** — `session-actor.ts` (`SESSION_ACTOR_PREFIX` + `sessionActorFromId(sessionId)` → `agent:session-<8-char sanitized prefix>`, reuses `seat.ts::sanitizeBranchSegment` semantics, THROWS on sanitize-to-empty input — never a bare prefix; the CLI session tier catches this and falls through to os-fallback; browser-safe by manual import review — `barrel-isolation.test.ts` pins only pinyin-pro/node-subpath reachability, not generic Node builtins); `task-workflow.ts::renewClaimForEvidence(claim, actor, nowIso)` (same-holder match fresh OR stale → NEW `{...claim, at: nowIso}`, foreign/absent → `null`, never mutates input — the SOLE renewal predicate both Task/Phase `appendEvidenceEntry` paths share); `session.ts::deriveLastActivityAt(plan, tasks)` (total — max `updated_at` over plan + child tasks; deliberate over-inclusion, any corpus write counts) + `bootstrapActivePlanSchema.last_activity_at` REQUIRED `z.string()` (fail-loud at the `bootstrapReportSchema.parse` self-check; schema and TS type must move together — `z.object` strips unknown keys).
- **Lifecycle graph** — `VALID_TRANSITIONS` in `schemas.ts` is the only authority on status moves. `isValidTransition(from, to)` and `getAllowedTransitions(from)` are the only public reads.
- **Config: env-var NAME, never plaintext (D-004)** — `sync.auth_token_env` stores the variable name (`"LORE_SYNC_TOKEN"` by default). `resolveSyncCredentials()` reads `process.env` at call time and fails loud (`VALIDATION_ERROR`) when missing or empty.
- **Telemetry never throws** — `JsonlTelemetry.record()` swallows IO errors; `close()` is idempotent; post-close `record()` is a no-op. Caller-visible behaviour does not change between `NoOpTelemetry` and `JsonlTelemetry`.
- **`frontmatter.ts::splitFrontmatter(text, mode)` is the shared `---`-delimiter split, refactored out of two independently hand-rolled copies (`MigrationService`'s `extractFrontmatter`, `ExportDocsService`'s two frontmatter regexes)** — delimiter splitting ONLY, no `yaml` dependency (callers `parse()` the returned `frontmatter` string themselves; this module has zero coupling to the `yaml` package). Two DISTINCT dialects, selected via a REQUIRED `mode` param (no implicit default — every caller states which dialect its file format uses): `"loose"` (migration-service's v1-markdown dialect — closing marker is the bare substring `"\n---"`, no trailing newline required, both `frontmatter`/`body` trimmed) vs `"strict"` (export-docs-service's v2-corpus-export dialect — opening delimiter must be `"---\n"` exactly, closing marker must be the full `"\n---\n"`, NEITHER side trimmed). Pre-processing (BOM-stripping, CRLF→LF normalisation) stays each caller's own responsibility — the two original sites disagreed on whether to do it, so baking either into this module would silently change one site's behaviour.

## Patterns

- **Zod is SSOT for runtime-validated shapes** — `TelemetryEventSchema`, `LoreConfigSchema`, `createDocInputSchema`, etc. Derived TS types come from `z.infer<typeof Schema>`; never duplicate the shape as a hand-written interface.
- **Type-specific validation via `superRefine`** — `createDocInputSchema` enforces `spec/task → parent_id`, `adr → extra.decision_status`, `knowledge → extra.sub_type`, `task → extra.plan_id`, `plan → extra.phases uniqueness` (`schemas.ts`).

### AI Plan-Outcome Assessment Schema (SPEC-026)

`assessment.ts` is a pure, browser-safe module (no IO, no `Date.now()`/`Math.random()`):
- `llmAssessmentOutputSchema` — the shape the AI judge's raw JSON response must match (`verdict`/`overall_score`/`ac_scores`/`gaps`/`recommendations`). Deliberately excludes `scope` and `judgment` — the model cannot know its own provider name, prompt version, or wall-clock duration; `AIProviderService.assessPlan` computes and layers those on after a successful parse.
- `assessmentResultSchema` = `llmAssessmentOutputSchema.extend({scope, judgment})` — the full persisted shape. This is what `knowledgeExtraSchema`'s `extra.assessment` branch validates against.
- `planBundleSchema` / `PlanBundle` — `{plan, spec?, tasks[]}`, assembled by `CorpusService.getPlanBundle`. Uses `z.custom<DocRecord>()` per slot (a light structural + `type` check, not a full `DocRecord` re-validation — `DocRecord` has no Zod schema anywhere else in this codebase; it's produced by the trusted store layer).
- `extractAssessmentJson(raw)` — tolerant JSON extraction from raw AI text: bare JSON → ` ```json ` fence → generic ` ``` ` fence → prose-wrapped (first `{` to last `}`). Never throws; returns a `VALIDATION_ERROR` Result when no JSON is found. Does NOT validate shape (that's `llmAssessmentOutputSchema`'s job) — a bare JSON array parses successfully here and fails schema validation downstream.
- `truncateSection(text, maxChars)` — single-section truncation primitive consumed by the prompt builder (`packages/lore/src/ai/assess-template.ts`) against `ai.assess.*` config budgets; truncated section names are collected into `judgment.truncated[]`.
- `renderAssessmentContent(result)` — deterministic Markdown rendering of a persisted `AssessmentResult` for the knowledge doc's `content` field. `extra.assessment` is the SSOT; `content` is generated ONLY by this function at creation time.

`knowledgeExtraSchema.sub_type` enum includes `"assessment"` — its `superRefine` requires a Zod-valid `extra.assessment` whenever `sub_type === "assessment"`. Manually creating a knowledge doc with `sub_type: "assessment"` (e.g. via `lore create` or the dashboard) without a matching `extra.assessment` payload fails loud — only `lore assess` / `lore_assess` write this sub_type.

`AiConfigSchema.assess` (`ai.ts`) holds the four character budgets (`max_plan_chars: 8000`, `max_spec_chars: 12000`, `max_task_chars: 4000`, `max_diff_chars: 24000`), mirroring the `ai.refine.max_input_chars` precedent.

**SPEC-040 additions (assessment.ts, T1+T2)**: `assessmentResultSchema` gained OPTIONAL `facts: assessmentFactsSchema` and `source_versions: sourceVersionRefSchema[]` — both service-computed and persisted VERBATIM by `AIProviderService.assessPlan`, never judge-writable. `llmAssessmentOutputSchema` gained OPTIONAL `dimension_scores` (three-dimension rubric: `outcome`/`evidence_integrity`/`scope_fidelity`), `typed_gaps`/`typed_recommendations` (structured findings, additive to the legacy `gaps`/`recommendations` string arrays — `deriveLegacyFindings` projects the former onto the latter at persist time, `AIProviderService._finalizeAssessment`), `unverifiable` (materials the judge couldn't verify), and `rubric_warning` (advisory strings — the service's `computeGroundingWarnings`, `packages/lore/src/service/ai-provider-service.ts`, D4 grounding cross-check, appends here too). `computeAssessmentFacts(bundle, declaredCriteria, diffMeta?)` is the D1 pure facts aggregator (AC coverage, task evidence completeness, `scope.dangling[]` drift, knowledge-capture, regression signals) — the prompt builder (`buildAssessPromptV6`, `packages/lore/src/ai/assess-template.ts`) renders it, never recomputes it. `ASSESS_TEMPLATES`/`getAssessTemplate` (same file) is the version-keyed prompt registry (SPEC-040 D6, `ASSESS_PROMPT_VERSION` now 6).

### Plan Phases Schema Invariants (SPEC-023)

`planExtraSchema` (in `schemas.ts`) governs plan extra fields:
- `phases?: Array<{name: string, description?: string}>` — max 30 entries (hard cap via `.max(30)`).
- `phases[].name` **must be unique** within the array — enforced by `superRefine` at write time (no built-in Zod uniqueness validator).
- Names are **case-sensitive, exact-match** at validation time; callers must trim whitespace before passing (service layer handles this).
- `phase?: string` — legacy singular field, deprecated. `lore migrate phases` converts it to `legacy_phase`. Do NOT write new code that reads `extra.phase` on plans (may be legacy or undefined). Read `extra.phases[]` instead.
- `legacy_phase?: string` — set by migration only. Informational. Not consumed by runtime code.

`taskExtraSchema` adds `phase?: string` — validated against parent plan's `extra.phases[].name` by `CorpusService` (not Zod, since it's cross-entity). Tasks without `extra.phase` are always valid regardless of plan phase declarations.

`planExtraSchema` also adds `ac_scope?: string[]` (`planAcScopeSchema` — non-empty array of non-empty AC-id strings, SPEC-040 §T2 D5). Shape only; cross-entity membership against the parent spec's declared `acceptance_criteria` is `CorpusService`'s job (`_createImpl`/`set`), same division of labor as `phase` above. Consumed by `computeAssessmentFacts` (`assessment.ts`) to compute `scope.scoped_ids`/`scope.dangling` and by `buildAssessPromptV6` (`packages/lore/src/ai/assess-template.ts`) to mark out-of-scope AC-table rows.
- **Parent-type contract** — `doc-type-rules.ts::PARENT_TYPE_CONTRACT` and `isValidParentType(child, parent)` are imported by `CorpusService` and `TreeCheckService`. Adding a new doc type requires updating this contract.
- **Graph helpers stay pure** — `graph-utils.ts::ancestorChainWalk` and `tree-blueprint.ts` operate on plain data; they don't take a `StoreInterface`. Callers fetch the data and pass it in.
- **Config side effects isolated to `loadConfig` / `saveConfig`** (now in `config-node.ts`, `@lore/core/node` subpath) — `parseConfig` and `loadConfigFromString` (in `config.ts`, default barrel) are pure and Result-returning; tests pass YAML strings, not file paths.
- **`doc-type-meta.ts::deriveTypeMeta(doc, opts?)` is the single derivation point for `DocSummary.meta`** (SPEC-036 §2 D3, browser-safe, no Node imports) — a discriminated union (`DocTypeMeta` in `types.ts`) keyed by `doc.type` (spec `kind` / adr `decision_status` / knowledge `sub_type` / plan `phase_count` / task `claimed_by?+claim_stale?+evidence_pass+evidence_fail`; `prd` → `undefined`). Never throws on arbitrary/legacy `extra` (null, wrong types, missing fields) — degrades by OMISSION, with exactly one documented default (absent `spec_kind` → `"feature"`, mirroring `CorpusService._createImpl`'s create-time default); reads `Date.now()` ONLY for `task.claim_stale`, and only when `opts.claimTtlMinutes` is supplied (a narrow, explicitly-noted deviation from this package's "no wall-clock reads" convention, forced by SPEC-036's fixed no-`nowIso` signature). Reuses `task-workflow.ts`'s exported `extractEvidence`/`extractClaim` (both now guard non-object `extra` via a local `safeTaskExtra` helper) rather than re-deriving evidence/claim parsing.
