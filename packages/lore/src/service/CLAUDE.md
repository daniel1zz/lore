# Module: service

## Purpose

Business logic layer. ~25 stateless services orchestrate `StoreInterface` calls and apply domain rules (lifecycle, parent-type validation, MDX placeholders, version snapshots, drift checks, AI generation, file-to-corpus sync, task/phase execution workflow, structured acceptance criteria, audit). All public methods return `Promise<Result<T, LoreError>>` — no thrown exceptions cross this boundary. `GateEnforcer` (`gate-enforcer.ts`) is a cross-cutting, non-store-holding module: an optional dependency `CorpusService`/`ReviewService`/`TaskWorkflowService`/`PhaseWorkflowService` consult before a gated write.

Full pre-compression mechanism walkthroughs (per-spec design decisions, byproduct fixes): corpus `knowledge-module-claude-md-snapshot-packages-lore-src-service`.

## Key Invariants

- **Stateless** — every service holds only a `StoreInterface` (+ optionally its own `Telemetry`). All persistent state lives in the store.
- **`Promise<Result<T, LoreError>>` everywhere** — no public method throws; internal helpers may, but every public surface catches and maps to `Result`.
- **`resolveDoc`/`resolveDocId`** (`resolve.ts`) is the SINGLE ID-or-slug-or-prefix lookup helper — ULID vs slug vs unique short prefix (`store.findByIdPrefix`; 2+ candidates → `VALIDATION_ERROR` listing them, 0 → `DOC_NOT_FOUND` with a truncation diagnostic). CLI/MCP/HTTP all inherit it — never reimplement per-adapter.
- **Approval edits reset to `draft`** — `CorpusService.update` auto-reverts an `approved` doc when title/content changes; this sanctioned reset is NOT itself a gated user transition. LEDGER exception (SPEC-103 M1): knowledge sub_types assessment/retro/handoff/uat fast-track draft→approved at create (audit `details.auto="ledger-fast-track"`) and, on edit, apply the reset THEN re-fast-track atomically in the same write (two audited steps — uniform reset semantics, one extra audit row). Task type is deliberately EXCLUDED (claim/ready/done assume draft preconditions). Kill-switch: `workflow.review.ledger_auto_approve`.
- **`ReviewService.approve` is judgment-gated for durable types** (SPEC-103 M2) — types in `workflow.review.judgment_required_types` (default spec+adr) require a ReviewJudgment for the CURRENT doc version; worst-decision-wins per version (reject > escalate > approve — same-version re-rolls can never outrank a reject); unlock = version bump + fresh approve-judgment or the audited `--override-judgment` escape. **That list scopes `reject` / missing-judgment / provenance-collision ONLY** — an `escalate` blocks approval for EVERY doc type once the list is non-empty, and the denial renders the judgment's `blocking_questions` verbatim so the writer learns what to answer from the refusal (`spec-an-escalate-blocks-approval-for-every-doc-type-and-the` D1/D4; an empty list stays a total kill switch per D3). D5: for an ungated type the question is "is ANY independent current-version decision an `escalate`?", never "is the WORST one?" — a co-recorded `reject` (suppressible opinion for such types) must not out-rank and destroy the escalate, so the service narrows the decision VECTOR it hands the predicate for ungated types instead of reinterpreting its verdict. Gated types keep the FULL vector: the same pair still blocks on the REJECT (anti-lottery). I1: a judgment whose judge tuple equals the doc's `extra.ai_provenance` does not count. `lore pending` hides task-type + ledger sub_types by default (M3, `--all` restores).
- **`TraceRecorder` is a fire-and-forget optional DI port** (SPEC-102, mirrors `recordGateSkip`) — absent in bare test constructions; a throwing recorder must NEVER alter the traced operation's `Result`; instruments `CorpusService.get`/`search` and `GateEnforcer` deny (kind=gate_deny, `details.layer` disambiguates hook vs service); `lore trace stats` reads never emit trace rows (no recursion).
- **`CorpusService.set` enforces `isValidTransition`** on any explicit status change (same check `ReviewService.approve`/`reject` apply) — illegal transitions return `INVALID_TRANSITION`.
- **`VersionService.restore` is atomic-ordered** — CAS `store.update` runs first; `versions`+`audit` rows are written ONLY on success (no phantom rows on `STALE_VERSION`).
- **Migration is idempotent** — `MigrationService` distinguishes `imported` vs `already_existed`.
- **`fs-walk.ts::walkFiles(dir, opts?)`** is the shared recursive dir-walker for `MigrationService`/`ExportDocsService`/the migration-coverage eval scenario — Dirent-based, `extensions` filter, `recursive` + `onError: "throw"|"skip"`. `service/`-local by design, dependency-free; not a general-purpose fs library.
- **Version log is append-only** — `restore` inserts an `action: "restore"` row, never deletes newer entries.
- **Context two-zone modules are pure** — `context-projection.ts` (parse/render/splice over managed marker sections, fingerprint `<!-- lore:managed section=<id> hash=<8hex> -->`, five-state incl. legacy fingerprint-less zone adoption) and the `claude-md-check.ts` admission extensions (`checkReferenceExistence` with an injected existence predicate, `detectNarrativeSmells` advisory-only, never exit-affecting; `computeHeadroom`/`computeHeadroomWarnings` report used/ceiling/remaining on every run and an advisory near-ceiling warning off a config `warn_threshold_fraction`, never a breach — same file's `lintMemoryFiles` alone still decides exit code) hold zero IO/store deps. IO enters only via `@lore/core` fs-ports in `context-facts.ts`; file-writing orchestration lives in `flows/context-flow.ts`, never in service/. Walk hygiene (AC-CTX-9): `collectContextFacts` skips dot-directories and gitignore-matched directories (layered per-directory `.gitignore` matchers via the `ignore` package, FsReadPort reads only — no child_process; static `EXCLUDED_DIR_BASENAMES` stays as exact-match fallback). Pre-write admission (AC-CTX-8): `runContextRefresh` runs the `claude-md-check.ts` ceiling check (SSOT with `lore status --check-claude-md`) on the spliced candidate BEFORE writing — breach → `VALIDATION_ERROR` naming every finding, no write. `spliceManagedSections` is the SOLE marker-splice implementation — `flows/setup-project-flow.ts` consumes it (AC-CTX-4 pin). SSOT: `spec-context-verb-family-two-zone-claude-md-anatomy-lore`.
- **`OutlineService` is regex-based** (no remark/unified/mdx dep) — self-closing tags only, unknown components stripped with a warning not an error. `renderResolvedToMarkdown` is the SOLE text-projection splice (descending-position walk keeps offsets stable); consumed by CLI `get` and `ExportDocsService`.
- **`CorpusService.get()`'s `resolve_mdx`/`resolved_components` are intentionally dead** — MDX resolution is adapter-side (`app.outlineService.resolve(doc)`); CorpusService must never import OutlineService.
- **`ExportDocsService`'s index allocation is collision-safe and self-healing** — duplicate corpus titles never alias another doc's `file_path`/`human_id` (`usedFilePaths`/`usedHumanIds` tracking, 999-attempt fail-loud); `repairCollisions` reconciles a corrupted `.lore/export-index.json`, reporting every repair (never silent). Splices MDX via an injected `ResolveDocBody` callback, never a direct OutlineService import.

## Patterns

- **Service per concern, no cross-service imports** — composition lives in `app.ts`; multi-service workflows are sequenced by the calling adapter (CLI/MCP/HTTP).
- **`CorpusService` is the only service wired to shared `Telemetry`**; `TaskWorkflowService`/`PhaseWorkflowService` carry their OWN `Telemetry` DI (cross-service calls are forbidden, so they can't piggyback).
- **`TaskWorkflowService`/`PhaseWorkflowService` write `extra.claim`/`extra.verification_evidence` directly via the store**, never through `CorpusService.update` — a bounded, documented bypass (CorpusService's approved→draft demotion is unreachable from these fields by construction). Their shared `appendEvidenceEntry` also renews a same-holder claim's `at` in the SAME CAS write (`renewClaimForEvidence`); foreign-holder/no-claim → byte-identical. `done()` (spec-workflow-hardening-evidence-red-vocabulary-claim-worktree §M3) extends this SAME direct-store bypass to `status` — the ONLY method on either service that writes it — walking `computeArchiveWalk`'s (`task-workflow-service.ts`, SSOT export) canonical `VALID_TRANSITIONS` path to `archived` one audited step at a time via each service's own `writeTaskStatus`/`writePhaseStatus`; refuses without ≥1 RUNNER-ATTESTED `result: "pass"` evidence (`attestation !== undefined`; audited `DoneOpts.overrideReason` escape) or a fresh foreign claim, idempotent no-op on an already-terminal doc — that short-circuit is evaluated BEFORE the attestation floor, so past closures never break retroactively. `done()` ALSO refuses a task declaring `extra.red_first: true` (task-red-first-discipline-is-asked-for-in-prose-but-never) that holds no `"expected-fail"`/`"fail"` evidence row — a SECOND, independent floor checked only after the `result:pass` floor succeeds, so neither can mask the other; `TaskWorkflowService.declareRedFirst` (`lore red-first <task>`) is the SOLE writer for that flag, mirroring the `ac_scope`/anchor dedicated-writer pattern (never `lore set`, never a create-time flag). A THIRD independent floor (task-every-ac-oracle-is-t-scoped-so-the-file-passes-is-attested) refuses when any test-file entry in `extra.file_anchors` lacks an attested UNFILTERED passing run — the `-t`-scoped AC rows attest each assertion, never "the file passes together". The file set comes from `file_anchors` (the existing declaration the `noAnchorOverlap` gate already consumes), NOT from parsing bound commands (shell-ambiguous) nor from runner output (`parseExecutedUnits` yields counts, not names); `isTestFileAnchor`/`commandRunsFileUnfiltered` (`@lore/core`, `attestation-completeness.ts`) own the predicates and FAIL CLOSED on any narrowing form they do not recognise — an unrecognised filter counts as filtered, never as a full run.
- **Stable public types live beside their owning service** (`PendingDoc` in review-service.ts, `Diff`/`FieldChange` in version-service.ts, `MigrationReport` in migration-service.ts, `TreeDrift`/`FixReport` in tree-check-service.ts) — never centralized into `core/types.ts`.
- **`TreeCheckService`** is the only service permitted to write the link table directly (parent_id ↔ link-table reconciliation).
- **One cross-doc read-orchestration locus per consumer family** — `CorpusService.getPlanBundle` (assess), `getReviewBundle` (judge), `resolveDeclaredAcIds` (AC `ac_ref` validation), `findFeedingSkill` (gate feeding-skill lookup) — never duplicated into an adapter.
- **`GateEnforcer.enforce(checkpoint, ctx)`** closes the service-layer gate bypass — SEVEN checkpoints (spec-create/spec-promote/plan-promote/task-claim/plan-close/phase-claim/review-judgment — the last added by SPEC-103 M2) share `checkpointRegistry` predicates unchanged. OPTIONAL trailing constructor arg on `CorpusService`/`ReviewService`/`TaskWorkflowService`/`PhaseWorkflowService` — every bare `new XService(store)` unit-test construction stays ungated (byte-identical pre-`GateEnforcer` behavior); only `app.ts` wires a real one. A config-disabled skip additionally fires a best-effort, never-blocking `gate_skipped` audit entry (D1: observability never changes the outcome).
- **`AuditService.verify`** joins `(doc_id, version)` PLUS an action-family check (never a bare action-string match — see `VERSION_ACTION_AUDIT_FAMILY`), and separately walks the FULL audit table as a tamper-evident hash chain (`walkAuditChain`, first-break diagnosis, optional external anchor cross-check via `.lore/audit-anchor.json`) — two independent oracles, not one.
- **`SetupService`/`ProjectSetupService` never import each other** (global-machine installer vs per-repo scaffold split, REGRESSION-tested).

## Service Map

| Service | Responsibility |
|---|---|
| `CorpusService` | CRUD, list, search, tree, link/unlink, status, `getPlanBundle`, `getReviewBundle`, `findFeedingSkill`, `resolveDeclaredAcIds` (telemetry-wired) |
| `ReviewService` | Pending queue, approve, reject; enforces `isValidTransition`; `PendingDoc.slug` always present |
| `VersionService` | Version log, unified diff (`diff` pkg), restore (append-only) |
| `OutlineService` | MDX placeholder resolution (whitelisted components) + `renderResolvedToMarkdown` text-projection splice |
| `MigrationService` | One-shot v1→v2 import (YAML-frontmatter MD → store) |
| `TreeCheckService` | Drift detection (missing/extra/misplaced/cycle/orphan/plan-terminality), auto-fix, parent_id↔link reconciliation. ⛔ `plan-terminality` (plan non-terminal while ≥1 child task exists and ALL are terminal) is deliberately NOT auto-fixable — transitioning a plan would fire the `plan-close` governance gate from inside a repair command; it is reported with its remediation command only |
| `AIProviderService` | AI provider dispatch + template render; `assessPlan` (plan judge), `judgeDoc` (review judge) |
| `SyncDocsService` | One-way file→corpus reconciler for spec files |
| `PhaseService` | add/list/remove/rename/migrate on `plan.extra.phases` |
| `TaskWorkflowService` | addEvidence/claim/release/done/ready — evidence log, advisory claim lease, evidence-validated atomic archival walk, computed readiness over `blocks` links (own telemetry) |
| `PhaseWorkflowService` | Same verb set as `TaskWorkflowService` (incl. `done`), scoped to `phase` docs; own `phase-claim` checkpoint; `recordChecklistVerifiedEvidence` is the sole `attestation` injection point for checklist-linked evidence |
| `PhaseMigrationService` | One-shot idempotent task→phase sweep (`lore migrate tasks-to-phases`) |
| `ExportDocsService` | One-way corpus→file exporter; collision-safe/self-healing `.lore/export-index.json`; MDX-spliced output |
| `JudgmentService` | record/latestFor/listFor AI review judgments; recordCalibration/computeCalibrationStats (Wilson-bound) |
| `StalenessProbeService` | probeBatch/probeOne for `lore review --staleness`; never mutates the probed doc, collect-and-continue on partial failure |
| `AuditService` | query (thin delegation) / verify (completeness join + hash-chain walk + anchor check) / getChainHead |
| `AcService` | add/list/remove/setCriterion on `spec.extra.acceptance_criteria`; aggregates per-AC evidence coverage across child plans' tasks (incl. `--adhoc` tasks whose `ac_scope` resolves to the spec). `setCriterion` edits a declared criterion IN PLACE — id and `mode` immutable, `ac_ref` never dangles (no removal window), and an `approved` spec is demoted to `draft` exactly as a prose edit would. SSOT: `spec-lore-ac-set-in-place-edit-of-a-declared-acceptance` |
| `VerifyRunnerService` | `verifyPlan` — trusted-runner orchestration for `lore verify` (command-provenance approval gate, env allowlist, attested evidence, declared-scope selection + its pre-flight refusals) |
| `SetupService` | planInstall/install/uninstall — global-machine installer over a resolved `targetDir`, manifest-authoritative |
| `ProjectSetupService` | Thin wrapper over `scaffoldProject` — per-repo `lore setup --project` scaffold |
| `GateEnforcer` | `enforce(checkpoint, ctx)` — service-layer runner for the six `lore gate` checkpoints |
| `RequirementService` | add/list/removeRequirement on `prd.extra.requirements`; mirrors `AcService` one tier up |
| `UatService` | `record` — sole write orchestrator for a structured UAT verdict, informs-links it to the plan |
| `DriftCheckService` | `checkDrift` — doc-code drift oracle over declared `extra.code_anchors`; also owns spec-target anchor RMW verbs (`addCodeAnchors`/`removeCodeAnchors`/`setCodeAnchors`) |
| `VerificationProjectionService` | `evidencePanel` — dashboard adjudication workbench projection; zero local derivation math, all coverage/ratio math imported from `@lore/core` |
