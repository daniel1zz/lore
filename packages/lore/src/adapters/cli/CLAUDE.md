# Module: adapters/cli

## Purpose

citty-based CLI adapter. Every subcommand lives in its own `commands/<name>.ts`, lazily imported by `index.ts` — that registry is the only count that stays true; ⛔ never restate the number here. Thin adapter only — no business logic; every command resolves args, calls a service via the App composition root, formats the result, and exits.

Full pre-eviction file (per-command mechanism walkthroughs, per-spec design decisions, rejected alternatives) is archived verbatim: `lore get knowledge-module-claude-md-snapshot-cli-adapter-pre-eviction`; the earlier pre-compression state: `knowledge-module-claude-md-snapshot-packages-lore-src-adapters`.

## Key Invariants

- **No business logic.** Commands resolve args → call `app.<service>.<method>()` → render output → map error to exit code. New rules belong in `packages/lore/src/service`, not here.
- **DB discovery lives in `corpus-resolution.ts`; App construction lives in `loader.ts`; neither lives in `utils.ts`.** `corpus-resolution.ts` builds on `@lore/core`'s pure `resolveCorpusProvenance` decision (spec-corpus-resolution-carries-provenance-and-a-foreign-write) and is vitest-safe (no `bun:sqlite`); `utils.ts` re-exports `findLoreDbPath` from it purely so pre-existing importers keep byte-identical import statements. `loader.ts` imports `bun:sqlite` (via `app.ts`) and is bun-only. Commands needing an App import `loadLoreApp` from `loader.ts`; commands only formatting errors import from `utils.ts`.
- **`loadLoreApp()` always returns `App` (never `Result<App>`)** — strips `config.sync` before `createApp`, so corpus-level commands never hit the TursoStore-failure path. `lore sync` manages TursoStore itself. ⛔ Any command mounting `startHttpServer` MUST pass `{surface: "http"}` — it keys the foreign-corpus-write guard on the ADAPTER; the `"cli"` default hands a long-lived server its launch directory, locking every HTTP write out of a nested worktree. Rationale + both oracles: `resolveForeignWriteProvenance`'s JSDoc.
- **`init`, `sync`, `setup` bypass `loadLoreApp`** — they run before a DB exists or manage their own store. Document the exemption when adding a new bootstrap-stage command.
- **Telemetry always wired** — `loadLoreApp` parses `.lore/config.yaml` on every command (failure → `NoOpTelemetry`). Never call `createApp(dbPath)` directly from a command.
- **Exit codes (SPEC-003 §5, centralised in `utils.ts::exitCode`)**: `1` STORE_ERROR/unknown/verify-assertion-failed, `2` CLI usage error, `3` DOC_NOT_FOUND/SLUG_NOT_FOUND, `4` validation/lifecycle/link errors, `5` STALE_VERSION/CLAIM_CONFLICT/WRITE_CONTENTION (the write-contention family — "someone else won the race, re-read and retry"), `6` AI_PROVIDER_ERROR, `7` NEEDS_APPROVAL. Exhaustive `never`-checked default branch — add new `LoreError` codes here too.
- **Actor resolution** (`utils.ts::resolveActor`/`resolveActorWithSource`) — precedence `--by` > `$LORE_ACTOR` > session tier (`CLAUDE_CODE_SESSION_ID`/`CLAUDE_SESSION_ID` → `agent:session-<id8>`) > worktree-derived `agent:<branch>` (SPEC-104: filesystem-only `.git`-file/`gitdir:`/HEAD walk, fires only when every named tier is exhausted AND cwd sits in a linked worktree; detached HEAD/unreadable → fail-open) > OS username (warns once). Never silently falls back to an empty string. ⛔ This chain answers WHO, never WHICH RUN: tier 3 is the only tier with a per-session discriminator and `$LORE_ACTOR` suppresses it, so two live sessions sharing one `LORE_ACTOR` is expected and legitimate — the run instance is a separate captured claim fact (`extra.claim.session_id`, written by the task AND phase workflow claim verbs).
- **Vitest-unsafe commands get a sibling `*-render.ts`/`*-input.ts` split** (also `-validation`/`-wiring`/`-precheck` suffixes; these siblings sit in `adapters/cli/` NEXT TO `commands/`, never inside it) — the command file transitively imports `loader.ts` (`bun:sqlite`, unresolvable by vitest); the split module imports only `@lore/core` + `utils.ts` so unit tests can exercise the pure rendering/parsing logic. Apply this pattern to any new command needing vitest coverage.
- **Strict unknown-flag rejection is ONE seam** (`strict-flags.ts::findUnknownFlag` + `wrapCommandStrict`, wired once per lazy import in `index.ts::wrapDefault`) — never patch individual commands. Violation → exit 2. Single-dash multi-char tokens also rejected exit 2 (`findSingleDashViolation`, SPEC-073).
- **No `lore set --anchor`** — `set` replaces `extra` wholesale; anchors have dedicated writers (`lore anchor add/rm`, `lore create --anchor/--code-anchor`). Same dedicated-writer shape applies to `extra.ac_scope` (`lore scope add/rm/list`, `lore create task --ac-scope` — task AND phase tiers, wiring `assertScopeFreeze`), `extra.validity` (`lore invalidate`), `extra.handoff` (`lore handoff`), `extra.phases`/`extra.claim`/`extra.verification_evidence` (task/phase workflow verbs only), `extra.red_first` (`lore red-first <task>`; no create-time flag) — `commands/set.ts` never edits these.
- **`gate`/`feed` are pre-flight/advisory pairs, and `LORE_GATE_BYPASS=1` is `gate`-scoped ONLY** — ⛔ never honored by `GateEnforcer.enforce()` in the write path; the one supported write-path escape is `workflow.gates.<checkpoint>.enabled: false`. Full block incl. the rationale that stops a future reader "fixing" the asymmetry: `knowledge-evicted-from-the-cli-adapter-module-doc-the-gate-feed`

## Patterns

- Subcommands are lazy ES module imports (`index.ts`'s `subCommands` map) — cold-start stays cheap.
- `findLoreDbPath`/`findLoreDbPathQuiet` (`corpus-resolution.ts`) both delegate to `resolveCorpus()`: own-tree hit, else the MAIN checkout via git-common-dir (SPEC M4, no local `.lore/` needed in a fresh worktree), else a miss — loud (exit 1 + `lore init` hint) vs quiet (`undefined`). `gate-bypass-audit.ts` re-exports the quiet one; `utils.ts` re-exports the loud one.
- Output helpers live in `utils.ts` (`formatTable`, `formatTree`, `formatNavigation`, `relativeTime`) — pure, no `process.exit`, reusable from tests.
- `formatError` renders multi-line stderr with contextual hints; add a case per new `LoreError` code.

## Subcommands

One line per command group — mechanism/design-decision detail lives in the archived snapshot or `lore search "<term>"`.

- `init` `get` `set` `delete` `list` `search` `tree` `link` `unlink` `log` `diff` `restore` `migrate` — corpus CRUD/history, thin `CorpusService`/`VersionService` pipes. ⛔ Read-surface validity gating is ONE seam (`fetchGatedFullDocs` over `service/validity-service.ts`) that every validity-carrying surface consumes instead of re-deriving the predicate: invalidated docs excluded by default, restored under `--include-invalid`, `validity_status` on every `--json` record. `--governed-by` is gated inside `CorpusService.listGovernedBy` so MCP inherits it — ⛔ never re-apply the exclusion CLI-side. `get`'s HUMAN render is a lossy projection that ANNOUNCES its loss (`get-render.ts::formatStructuredExtraNotice`), keyed on what THAT render actually surfaced, ⛔ never a static key list; `--json` bytes untouched. ⛔ Residual: `ready` FILTERS correctly but carries no validity key.
- `create` — doc creation; `--anchor`/`--code-anchor` at creation time, `--supersedes` composes create+invalidate.
- `status` — health snapshot; `--check-tree`/`--check-drift`/`--check-requirements`/`--check-claude-md`/`--check-prd-budget` deterministic CI oracles, composable exit precedence. ⛔ `total_docs`/`by_type`/`by_status` are LIVE counts; `invalid_docs` is ALWAYS present (`0` included) and printed every human run — an omitted count is the same silence as an uncounted retraction. `last_updated` still spans retracted docs: a retraction IS a change. ⛔ Its floor is **0.97**, but the FOUR anchored module docs are held to **0.9** by `tests/unit/service/claude-md-eviction-floor.test.ts` — so this command says "within budget" while the suite reddens (measured): `knowledge-evicted-from-the-service-module-doc-reviewservice-s`. `--check-claude-md` also reports WHOSE ceilings it used — `budget_source`/`budget_substitution` in `--json`, stderr notice on substitution. ⛔ Its exit code is deliberately UNCHANGED when budgets are substituted: `assets/hooks/claude-md-guard.sh` maps 0→allow, 3→block and every other code to fail-open, so a refusal code would turn "measured against the wrong budgets" into "not measured at all", silently. ⛔ `pass_unfalsified_count` (criteria green but never observed able to go red; also now excludes `fail_superseded`/`not_measured` facts, spec-oracle-tier-falsifiability-a-criterion-never-observed-red M4/M5) and `unclaimed_oracle` (test-name filter values no declared criterion binds) are reported UNCONDITIONALLY and are exit-code-INERT by decision, not by omission: a live, nonzero count of existing criteria sit in that state at any given moment (`lore status --json`'s own field is the only current number — never restate a literal here, it drifts on every `lore evidence`), so gating on it would put the corpus in violation on the landing commit — the back-catalogue is grandfathered by a written exemption in `spec-oracle-tier-falsifiability-a-criterion-never-observed-red` §Out of scope, never by authored red runs. `--enumerate <field>` (AC-FR-5) returns the MEMBER LIST behind any registered `*_count` field (`COUNT_FIELD_ENUMERATORS`) — every count on this branch derives its number from that list's length, never a separately-tallied counter; an unregistered field name is refused, naming it.
- `pending` `approve` `reject` `review` — review workflow (SPEC-005/034/103); `review` adds structured AI judgment + `--staleness` probes (SPEC-044) + `backfill-ledger` (one-shot); approve/reject implicitly capture calibration (SPEC-035). `pending` hides task-type + ledger sub_types by default (`--all` restores); `approve` of spec/adr demands a current-version approve-judgment (worst-decision-wins; audited `--override-judgment` escape).
- `trace` — `trace stats [--since] [--json] [--raw-queries] [--enumerate <field>]` read-only aggregation over `trace_events` (SPEC-102); aggregates only unless `--raw-queries` or `--enumerate`. `--enumerate <field>` carries the SAME AC-FR-5 registry contract `status --enumerate` documents above (`TRACE_COUNT_FIELD_ENUMERATORS`), strengthened two ways: the registry is keyed by a type DERIVED from the report shape, so a new `*_count` with no enumerator FAILS TO COMPILE; and enumerating `zero_hit_search_count` withholds literal query text unless `--raw-queries` is also passed. Startup runs bounded-batch retention pruning (`trace.retention_days`) unless `trace.enabled=false`.
- `claim` `release` `evidence` `ready` `done` — task/phase execution workflow (SPEC-025/042/056); target-type dispatch tries `TaskWorkflowService` first, falling back to phase workflow only on a `type: "phase"` validation rejection. `done` requires ≥1 RUNNER-ATTESTED pass row; `evidence` requires `--capture` or `--oracle manual` for a self-reported pass to stick. Full mechanism (capture-timeout semantics, `--ac-scope`/`--declare-no-new-tests` red-first floor, `capture_source_*_count` enumerator contract): `knowledge-evicted-from-the-cli-adapter-module-doc-the-claim`.
- `red-first` — dedicated writer for a task's `extra.red_first` claim (`TaskWorkflowService.declareRedFirst`); see commands/red-first.ts's module header.
- `phase` — `add/list/rm/rename` (plan-level `extra.phases[]`, SPEC-023) plus `status/checklist/track` (phase-document verbs, SPEC-056).
- `assess` — LLM-as-judge plan-outcome assessment (SPEC-026); no non-AI mode.
- `audit` `calibration` — audit-trail query + `--verify` chain-integrity walk (SPEC-035/079), `audit anchor` pins `.lore/audit-anchor.json`; calibration stats are read-only.
- `ac` `requirement` — AC-as-code (SPEC-038) and PRD requirement inventory (SPEC-055) dedicated writers; `ac add --covers` links them.
- `verify` — trusted runner executing script-mode ACs, runner-attested evidence only (SPEC-039, §M2 env allowlist + command-provenance approval).
- `gate` `feed` — see Key Invariants; groups covering spec-create/spec-promote/plan-promote/task-claim/phase-claim and the matching feed checkpoints incl. `task-start`/`phase-start`/`session-resume`. ⛔ `feed task-start` REFUSES a RETRACTED task (exit 4 / MCP `isError`, NO pack, unconditional `RETRACTED` + `invalid_at=` tokens), implemented in `flows/task-feed-flow.ts` so both surfaces inherit it. UNPARSEABLE `extra.validity` is instead ANNOUNCED in `constraints`, ⛔ never read as live in silence.
- `bootstrap` `handoff` — S1 session pointer-set (read-only) and the sole write path for `knowledge/handoff` docs (SPEC-041).
- `anchor` `invalidate` — dedicated writers for `extra.file_anchors` (task) / `extra.code_anchors` (spec AND knowledge, `path[#Symbol]` grammar) and `extra.validity` (bi-temporal invalidation, SPEC-043). ⛔ The non-resolving advisory below is TASK-ONLY and consumes the FILE-anchor grammar — applying it to a `path#Symbol` anchor would probe the whole string as a literal path and report non-resolving every time, a guaranteed-false advisory; spec and knowledge are checked by `--check-drift` instead. `anchor add` + `create task --anchor` print a NON-BLOCKING stderr advisory naming each declared anchor that does not resolve on disk (exit code untouched, anchor stored — `service/anchor-resolution.ts`); `ready <plan>` injects the same cwd-rooted probe and carries `anchor_resolution` in `--json`, where `{probed:false}` (MCP/HTTP `ready`) is deliberately distinct from `{probed:true, unresolved:[]}`.
- `sync` `sync-docs` `export-docs` — Turso replica management, one-shot dir→corpus scaffold (SPEC-018), corpus→`.md` reverse sync (SPEC-021).
- `serve` `dashboard` `agent` `eval` — HTTP adapter mount, in-process dashboard (packaged single-process by default: embedded static assets + one-time-nonce bootstrap redirect; `--dev` retains the Vite-child + injected-token topology of SPEC-016), API-key management (⛔ NOT an MCP launcher — MCP is the top-level `--mcp-server` flag), evaluation scenarios.
