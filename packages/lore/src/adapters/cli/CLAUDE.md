# Module: adapters/cli

## Purpose

citty-based CLI adapter. Every subcommand lives in its own `commands/<name>.ts`, lazily imported by `index.ts` — that registry is the only count that stays true (a number restated here goes stale silently; the previous "32" had drifted to 61). Thin adapter only — no business logic; every command resolves args, calls a service via the App composition root, formats the result, and exits. Full pre-compression file (mechanism detail, per-spec design decisions, module headers to read) is archived verbatim: `lore get knowledge-module-claude-md-snapshot-packages-lore-src-adapters`.

## Key Invariants

- **No business logic.** Commands resolve args → call `app.<service>.<method>()` → render output → map error to exit code. New rules belong in `packages/lore/src/service`, not here.
- **DB discovery + App construction live in `loader.ts`, not `utils.ts`.** `loader.ts` imports `bun:sqlite` (via `app.ts`) and is bun-only; `utils.ts` is vitest-reachable and must stay sqlite-free. Commands needing an App import `loadLoreApp` from `loader.ts`; commands only formatting errors import from `utils.ts`.
- **`loadLoreApp()` always returns `App` (never `Result<App>`)** — strips `config.sync` before `createApp`, so corpus-level commands never hit the TursoStore-failure path. `lore sync` manages TursoStore itself.
- **`init`, `sync`, `setup` bypass `loadLoreApp`** — they run before a DB exists or manage their own store. Document the exemption when adding a new bootstrap-stage command.
- **Telemetry always wired** — `loadLoreApp` parses `.lore/config.yaml` on every command (failure → `NoOpTelemetry`). Never call `createApp(dbPath)` directly from a command.
- **Exit codes (SPEC-003 §5, centralised in `utils.ts::exitCode`)**: `1` STORE_ERROR/unknown/verify-assertion-failed, `2` CLI usage error, `3` DOC_NOT_FOUND/SLUG_NOT_FOUND, `4` validation/lifecycle/link errors, `5` STALE_VERSION/CLAIM_CONFLICT/WRITE_CONTENTION (the write-contention family — "someone else won the race, re-read and retry"), `6` AI_PROVIDER_ERROR, `7` NEEDS_APPROVAL. Exhaustive `never`-checked default branch — add new `LoreError` codes here too.
- **Actor resolution** (`utils.ts::resolveActor`/`resolveActorWithSource`) — precedence `--by` > `$LORE_ACTOR` > session tier (`CLAUDE_CODE_SESSION_ID`/`CLAUDE_SESSION_ID` → `agent:session-<id8>`) > worktree-derived `agent:<branch>` (SPEC-104: filesystem-only `.git`-file/`gitdir:`/HEAD walk, fires only when every named tier is exhausted AND cwd sits in a linked worktree; detached HEAD/unreadable → fail-open) > OS username (warns once). Never silently falls back to an empty string. ⛔ This chain answers WHO, never WHICH RUN: tier 3 is the only tier with a per-session discriminator and `$LORE_ACTOR` suppresses it, so two live sessions sharing one `LORE_ACTOR` is expected and legitimate. The session instance is a separate captured claim fact (`extra.claim.session_id`, written by `TaskWorkflowService.claim` AND `PhaseWorkflowService.claim` — the latter's `processEnv` is wired in `phase-wiring.ts`, the ONE argument its whole production capture rests on); `lore gate task-claim`/`phase-claim` both read the same env vars for pre-flight parity with the real claim.
- **Vitest-unsafe commands get a sibling `*-render.ts`/`*-input.ts` split** (`assess-render.ts`, `pending-render.ts`, `create-task-validation.ts`, `review-render.ts`, `handoff-input.ts`, `task-feed-render.ts`) — the command file transitively imports `loader.ts` (`bun:sqlite`, unresolvable by vitest); the split module imports only `@lore/core` + `utils.ts` so unit tests can exercise the pure rendering/parsing logic. Apply this pattern to any new command needing vitest coverage.
- **Strict unknown-flag rejection is ONE seam** (`strict-flags.ts::findUnknownFlag` + `wrapCommandStrict`, wired once per lazy import in `index.ts::wrapDefault`) — never patch individual commands. Violation → exit 2. Single-dash multi-char tokens also rejected exit 2 (`findSingleDashViolation`, SPEC-073).
- **No `lore set --anchor`** — `set` replaces `extra` wholesale; anchors have dedicated writers (`lore anchor add/rm`, `lore create --anchor/--code-anchor`). Same dedicated-writer shape applies to `extra.ac_scope` (`lore scope add/rm/list`, `lore create task --ac-scope` — task AND phase tiers, wiring `assertScopeFreeze`), `extra.validity` (`lore invalidate`), `extra.handoff` (`lore handoff`), `extra.phases`/`extra.claim`/`extra.verification_evidence` (task/phase workflow verbs only), `extra.red_first` (`lore red-first <task>` — task-red-first-discipline-is-asked-for-in-prose-but-never; no create-time flag either, since the claim is typically made after a task already exists) — `commands/set.ts` never edits these.
- **`gate`/`feed` are pre-flight/advisory pairs**: `gate <checkpoint>` runs a candidate write through the SAME `../../service/checkpoint-registry.js` predicates the service layer enforces, before the doc exists (`LORE_GATE_BYPASS=1` short-circuits exit 0, best-effort audits the bypass); `feed <checkpoint>` PULLs the governing rule/context ahead of writing. Both dispatch via checkpoint-name tables in their command files, never if/else chains. ⛔ `LORE_GATE_BYPASS=1` is scoped to `gate <checkpoint>` ONLY — it is NEVER honored by `GateEnforcer.enforce()` (`../../service/gate-enforcer.ts`), the SAME predicates running inline inside `CorpusService.create`/`set`, `ReviewService.approve`, `TaskWorkflowService.claim` (CLI writes, MCP, HTTP dashboard). Restricting the bypass to `lore gate` alone (Design Decision Option B, task-lore-gate-bypass-honored-by-lore-gate-subcommands-but) was deliberate: a bare env var governs the whole OS process, so honoring it in the write path too would silently disarm gates for every remote caller sharing a long-lived `lore serve` process's environment. A write-path denial with the variable set now NAMES that boundary in its message and points at the actually-supported escape hatch, `workflow.gates.<checkpoint>.enabled: false`.

## Patterns

- Subcommands are lazy ES module imports (`index.ts`'s `subCommands` map) — cold-start stays cheap.
- `findLoreDbPath` walks `cwd` → root for `.lore/lore.db`; on a miss, falls back to the MAIN checkout's corpus when cwd is inside a linked git worktree (`git rev-parse --git-common-dir` vs `--git-dir`, SPEC M4) — no local `.lore/` needed inside a fresh `git worktree add` tree; still absent → exits 1 + `lore init` hint. `gate-bypass-audit.ts::findLoreDbPathQuiet` shares the same fallback (`findMainCheckoutLoreDb`), degrading to `undefined` instead of exiting.
- Output helpers live in `utils.ts` (`formatTable`, `formatTree`, `formatNavigation`, `relativeTime`) — pure, no `process.exit`, reusable from tests.
- `formatError` renders multi-line stderr with contextual hints; add a case per new `LoreError` code.

## Subcommands

One line per command group — mechanism/design-decision detail lives in the archived snapshot or `lore search "<term>"`.

- `init` `get` `set` `delete` `list` `search` `tree` `link` `unlink` `log` `diff` `restore` `migrate` — corpus CRUD/history, thin `CorpusService`/`VersionService` pipes.
- `create` — doc creation; `--anchor`/`--code-anchor` at creation time, `--supersedes` composes create+invalidate.
- `status` — health snapshot; `--check-tree`/`--check-drift`/`--check-requirements`/`--check-claude-md`/`--check-prd-budget` deterministic CI oracles, composable exit precedence.
- `pending` `approve` `reject` `review` — review workflow (SPEC-005/034); `review` adds structured AI judgment + `--staleness` probes (SPEC-044) + `backfill-ledger` (SPEC-103 one-shot); approve/reject implicitly capture calibration (SPEC-035). SPEC-103: `pending` hides task-type + ledger sub_types by default (`--all` restores); `approve` of spec/adr demands a current-version approve-judgment (worst-decision-wins; audited `--override-judgment` escape).
- `trace` — `trace stats [--since] [--json] [--raw-queries]` read-only aggregation over `trace_events` (SPEC-102): counts-by-kind, deny-by-checkpoint (hook/service layer-tagged), zero-hit searches, never-read docs, read-side deny→retry gap; aggregates only unless `--raw-queries`. Startup runs bounded-batch retention pruning (`trace.retention_days`) unless `trace.enabled=false`.
- `claim` `release` `evidence` `ready` `done` — task/phase execution workflow (SPEC-025/042/056; `done` per spec-workflow-hardening-evidence-red-vocabulary-claim-worktree §M3); target-type dispatch tries `TaskWorkflowService` first, falls back to phase workflow only on a `type: "phase"` validation rejection. `done` additionally validates ≥1 RUNNER-ATTESTED `result: "pass"` evidence entry (a self-reported `lore evidence` pass no longer suffices; audited escape `--override-attestation "<reason>"`, blank → exit 2) and no fresh foreign claim before walking `VALID_TRANSITIONS` to `archived` one audited step at a time (idempotent no-op on an already-terminal doc); ALSO refuses a task declaring `extra.red_first: true` with no `"expected-fail"`/`"fail"` evidence row (task-red-first-discipline-is-asked-for-in-prose-but-never); for every OTHER task (the opt-out default) ALSO refuses a declared `extra.ac_scope` with zero red rows unless `--declare-no-new-tests "<reason>"` is supplied (task-a-non-empty-output-tail-can-be-hand-authored-prose-and-the — NOT named `--no-new-tests`, which citty's mri parser would silently negate-and-discard). `evidence` additionally refuses a self-reported `--result pass` lacking a genuinely non-empty `output_tail` UNLESS `--capture` (spawns `--command` itself, verifies the real exit code, stamps `capture_source: "runner"`) was used — every write stamps `capture_source: "runner"|"self-report"`, never omitted, never inferred from the tail's shape. `--capture`'s window is `workflow.evidence.capture_timeout_ms` (default 600000 ms; the ONLY site of that number, `resolveCaptureTimeoutMs`) — never a module constant, since the honest runtime of a scoped oracle grows with the suite while a hang detector does not. ⛔ Exceeding it is a FAILED capture: loud exit-4 refusal naming window+elapsed+knob, NOTHING recorded — never a silent downgrade to the weaker `self-report` class. Timeout is MEASURED (`ETIMEDOUT` OR monotonic elapsed ≥ window), never inferred from `status === null`: a timed-out child that traps SIGTERM exits 0 or 3 (measured), so that predicate would have recorded a runner-attested PASS for an oracle that never finished.
- `red-first` — dedicated writer for a task's `extra.red_first` claim (`TaskWorkflowService.declareRedFirst`); see commands/red-first.ts's module header.
- `phase` — `add/list/rm/rename` (plan-level `extra.phases[]`, SPEC-023) plus `status/checklist/track` (phase-document verbs, SPEC-056).
- `assess` — LLM-as-judge plan-outcome assessment (SPEC-026); no non-AI mode.
- `audit` `calibration` — audit-trail query + `--verify` chain-integrity walk (SPEC-035/079), `audit anchor` pins `.lore/audit-anchor.json`; calibration stats are read-only.
- `ac` `requirement` — AC-as-code (SPEC-038) and PRD requirement inventory (SPEC-055) dedicated writers; `ac add --covers` links them.
- `verify` — trusted runner executing script-mode ACs, runner-attested evidence only (SPEC-039, §M2 env allowlist + command-provenance approval).
- `gate` `feed` — see Key Invariants; command groups covering spec-create/spec-promote/plan-promote/task-claim/phase-claim and the matching feed checkpoints incl. `task-start`/`phase-start`/`session-resume`.
- `bootstrap` `handoff` — S1 session pointer-set (read-only) and the sole write path for `knowledge/handoff` docs (SPEC-041).
- `anchor` `invalidate` — dedicated writers for `extra.file_anchors`/`extra.code_anchors` (dispatches by target doc type) and `extra.validity` (bi-temporal invalidation, SPEC-043).
- `sync` `sync-docs` `export-docs` — Turso replica management, one-shot dir→corpus scaffold (SPEC-018), corpus→`.md` reverse sync (SPEC-021).
- `serve` `dashboard` `agent` `eval` — HTTP adapter mount, in-process dashboard (packaged single-process by default: embedded static assets + one-time-nonce bootstrap redirect; `--dev` retains the Vite-child + injected-token topology of SPEC-016), API-key management (NOT an MCP launcher — MCP is the top-level `--mcp-server` flag), evaluation scenarios.
