# Module: ai

## Purpose

Runtime AI provider implementations, registry builder, template engine, assess/review judge prompt builders, AI-default resolution, and in-memory test double. Wires the `AIProvider` interface (defined type-only in `@lore/core`) to concrete spawn-based execution.

Full pre-eviction file (per-prompt-version change narratives, per-spec design decisions, measured judge failure modes) is archived verbatim: `lore get knowledge-module-claude-md-snapshot-packages-lore-src-ai-frozen`.

## Key Invariants

- **Type-only interface in `@lore/core`, concrete classes here** — `AIProvider` is declared in `packages/core/src/ai.ts` and imported by `ClaudeCliProvider`/`InMemoryAIProvider` via `@lore/core`. ⛔ No reverse dependency: `@lore/core` never imports from `packages/lore/src/ai/`.
- **All providers use ClaudeCliProvider in v1** — `buildProviderRegistry` constructs one for every entry in the merged config map. A future SPEC adds a `kind` discriminator and an `HttpProvider`.
- **User provider entries REPLACE whole built-in entries** — no deep-merge. The user owns the full `{ command, args, timeout_ms }` block or none.
- **`InMemoryAIProvider` ships in src/ not tests/** — so any test in any package (including `@lore/core`'s) can import it without path hacks.
- **Never throw** — all public async methods return `Promise<Result<T, LoreError>>`. `ClaudeCliProvider.generate` wraps `Bun.spawn` in try/catch to map ENOENT to `AI_PROVIDER_ERROR`.
- **Prompt TEXT lives here, never in `@lore/core`** (SPEC-026 D8) — `assess-template.ts` owns `ASSESS_PROMPT_VERSION`, `review-template.ts` owns `REVIEW_PROMPT_VERSION`. `@lore/core`'s `assessment.ts`/`review-checks.ts` stay limited to schemas + pure data helpers (truncation, JSON extraction, content rendering, `runDeterministicChecks`), matching the `task-workflow.ts` precedent: core = schemas + pure helpers, no prompt strings.
- **This module RENDERS; `@lore/core` COMPUTES** (SPEC-038 D6) — coverage cells come from `computeAcCoverage`, deterministic facts from `computeAssessmentFacts`, AC-vagueness verdicts from `lintAcQuantifiability`, diff-file classification from `listDiffFiles`. ⛔ Each fact is derived at exactly ONE site and passed in; a renderer that re-derives one lets the prompt and the enforcing check disagree about what the judge was shown. `BuildAssessPromptResult.declaredAcIds` carries the extracted id list out to `AIProviderService.assessPlan`, which builds `validateAcIdContainment`'s `Set` from it — one extraction site, no drift.
- **Both prompt families are VERSION-KEYED REGISTRIES, and a landed version is FROZEN** — `ASSESS_TEMPLATES: Record<number, AssessTemplateFn>` and `REVIEW_TEMPLATES: Record<string, ReviewTemplateFn>`. ⛔ A new prompt spec ADDS a key; it never mutates an existing one. `getAssessTemplate(version)` is the Result-returning lookup (`err(AI_PROVIDER_ERROR)` naming an unregistered version, never a throw) — `assessPlan` calls it rather than a builder directly. Byte-identity of a frozen version is pinned where it matters: `buildReviewPromptV1` is locked by the `tests/fixtures/review-prompt-v1.txt` fixture, and every "no structured input" fallback path (a spec with 0 declared ACs, a non-spec doc) must render byte-identically to the previous version.
- **A truncation notice must NAME what was cut, or it fails both ways** — "present but unseen" alone was measured to produce both a false "missing" escalation and an obedient judge that could not say which references were unverifiable. So: `truncateDiffByFile` dropping files makes `buildAssessPrompt` append a per-path Truncation Manifest (grouped by `classifyDiffFilePriority`) built from the SAME `omittedFiles` array that feeds `truncated[]` — no second bookkeeping — plus a hard instruction not to score a dropped file as missing; and `extractSectionHeadings` scans the FULL parent content (⛔ never the truncated copy — vacuous otherwise), splitting shown/omitted at `contextSection.text.length` (⛔ not `max_context_chars`, which can differ at a surrogate-pair boundary). ⛔ Never a silent empty list: zero headings → "cannot be named", all shown → "every heading visible", none shown → a loud "NONE visible" prefix. ⛔ **From v6 the document under review is NEVER cut** (BR-268, D9): only the parent context keeps a budget (`max_context_chars`); a body the provider cannot take is an AI failure (exit 6), and a v6 judgment is never stamped `truncated`. v1-v5 stay frozen and still cut at `max_doc_chars` (default `FROZEN_DOC_CHARS`) — `assembleReviewPrompt`'s `wholeDocument` flag is set only by v6; v6 also renders baseline rule examples and declared commands (BR-960). A stored `truncated` judgment of ANY version can never approve (BR-269, `JUDGMENT_INPUT_TRUNCATED`). Rationale: `knowledge-assess-diff-truncation-systematically-hides-tests-from`.
- **An advisory is rendered, carried, and NEVER allowed to move a verdict** (SPEC-053) — `buildReviewPromptV2` renders an AC-quantifiability section only when the doc declares ≥1 AC, plus an `advisory[]` JSON field and the exported `ADVISORY_ONLY_CLAUSE`; `_finalizeJudgment` passes `parsed.advisory` through verbatim. ⛔ Never re-derived, never permitted to alter the decision — the prompt forbids it. The `kind` enum SSOT + `reviewAdvisorySchema` live in `@lore/core`; CLI rendering is `renderAdvisoryBlock` (pure `""`-no-op when absent).
- **Declared scope narrows what the judge may cite** (SPEC-040 D5) — when a plan declares `extra.ac_scope`, `renderStructuredAcTable`'s `scopedIds` param annotates out-of-scope rows AND `declaredAcIds` narrows to the scoped subset, so containment enforces the PLAN's scope, not the spec's full declared set.
- **`InMemoryAIProvider`'s `sequence` mode is FIFO and fails loud when exhausted** (SPEC-026 D9) — `shift()` per `generate()`; more calls than responses returns `AI_PROVIDER_ERROR` rather than silently reusing the last response. A test that under-scripts its sequence is a test bug, and this surfaces it instead of masking it.
- **`assess-golden-aggregation.ts` is arithmetic ONLY** (SPEC-040 D7) — pure, no IO, no provider or template import; consumed by `scripts/assess-golden.ts`. `deriveGoldenDirectionLabel`/`computeMajorityLabel` (documented conservative tie-break `not_met > partial > met`)/`aggregateGoldenRun` (non-inferiority verdict, ties pass). ⛔ It never invokes a live provider; unit-tested with scripted labels.

## Patterns

- **No module-level IO** — `ClaudeCliProvider` only spawns inside `generate()`, never in the constructor. Registry construction is purely synchronous object creation.
- **Timeout watchdog** — `setTimeout` + `proc.kill("SIGTERM")` + `clearTimeout` on normal completion. The killer timer is ALWAYS cleared, to prevent stale-timer surprises on reuse.
- **Hermetic judge spawn (SPEC-030 AC-HJ-1)** — `generate` never builds `Bun.spawn`'s `cwd`/`env`/`args` inline; it calls `buildHermeticSpawnSpec(cfg, {sourceEnv, tmpDir})` (`hermetic-spawn.ts`), a pure function so the sanitization is vitest-testable even though the call site is bun-only. The spec: neutral cwd (OS tmpdir, not the host project dir), sanitized env (denylist strips `CLAUDECODE` + `CLAUDE_*`; everything else, including auth vars, passes through), and — ONLY when the configured command's basename is `claude` — the official `--setting-sources ""` isolation flag. A custom judge command gets no injected flag. (`--bare` was rejected: it restricts auth to `ANTHROPIC_API_KEY`/`apiKeyHelper` only.)
- **Template rendering is two-pass** — conditionals (`{{#key}}…{{/key}}`) before substitutions (`{{key}}`), so vars inside a collapsed block never partially expand.
- **assess has no non-AI mode** (SPEC-026 D5) — `isAssessAiBraked(resolveAiDefault(undefined, surface, configDefaults))` is the ONLY correct gate: the built-in per-surface AI-off default (agent/mcp/http_token) must NOT brake assess, only an EXPLICIT config override should. ⛔ Checking `resolveAiDefault(...).ai === false` directly, without the source-tier check, braked assess on every agent/mcp call and defeated D5 entirely.
